## 1. Что меняется в целом

Сейчас весь код написан с допущением «драйвер один, мотор один». Это допущение
сидит примерно в **100 местах в 6 файлах**:

| Что зашито | Где | Сколько мест |
|---|---|---|
| адрес драйвера `0` (`UART_TMC_DRIVER_ADDR`) | `tmc-uart` | 3 |
| вызовы `read_tmc_reg` / `write_tmc_reg` без адреса | `tmc-driver`, `tmc-error`, `main` | ~35 |
| пины `ENABLE_PIN`, `STEP_PIN`, `DIR_PIN` | `tmc-driver`, `stepper` | ~9 |
| один объект `stepper` | `stepper.cpp` | ~35 |
| один флаг `motion_blocked` | `stepper.cpp` | ~9 |
| одно состояние аварии `fault` | `tmc-error.cpp` | ~16 |
| токи `TMC_IRUN` / `TMC_IHOLD`, `PWM_GRAD = 51` | `tmc-current.h`, `tmc-driver.cpp` | ~20 |
| скорость ведения, шагов на оборот | `stepper` | ~19 |

**Железо простое** (несколько проводов). **Основная работа — в коде**: провести
через все модули понятие «ось», чтобы каждая функция знала, с каким драйвером
и мотором работает.

Оценка объёма:

| Шаг | Объём |
|---|---|
| железо | 1 вечер |
| шаг 1 — рефакторинг на одной оси | **самый большой**: затрагивает все модули |
| шаги 2–3 — второй драйвер и мотор | небольшие, если шаг 1 сделан аккуратно |
| шаг 4 — сторож | средний |
| шаг 5 — команды движения | небольшой |

## 2. Решения, которые нужно принять до начала

| # | Вопрос | Варианты | Рекомендация |
|---|---|---|---|
| 1 | **Авария на одном драйвере**: что делать со вторым мотором? | остановить только сломавшуюся ось / остановить обе | **остановить обе**: для наведения нужны обе оси, позиция одной без другой бесполезна. Перенастраивать — только сломавшийся драйвер |
| 2 | **Пин EN** | общий на оба драйвера / свой у каждого | **свой у каждого**: ось можно выключить отдельно, сторож может перенастроить один драйвер, не трогая второй |
| 3 | **Числа для DEC** | зубья червяка 65 или 130 ⚠️, передача ремня, микрошаг | посчитать зубья (см. [belt-drive.md](belt-drive.md), 3.1) до шага 3 |
| 4 | **Когда делать относительно ремней** | до / после | рефакторинг (шаг 1) — **сейчас**, он не зависит от механики. Передачу и микрошаг потом просто поменять в конфиге |

## 3. Железо

### 3.1. Схема подключения

TMC2209 умеет работать **вдвоём на одном проводе UART**: у каждого драйвера
свой адрес 0…3, он задаётся пинами MS1/MS2 (datasheet стр. 15, 18).

```
                 ┌────────────────────────────┬────────── PDN_UART  TMC #0 (RA)
ESP TX ──[1 кΩ]──┤                            │           MS1 = GND, MS2 = GND → адрес 0
ESP RX ──────────┘                            └────────── PDN_UART  TMC #1 (DEC)
                                                          MS1 = 3.3 В, MS2 = GND → адрес 1

GPIO 5  ──── STEP  RA              GPIO ?  ──── STEP  DEC    ← новый пин
GPIO 4  ──── DIR   RA              GPIO ?  ──── DIR   DEC    ← новый пин
GPIO 6  ─┬── EN    RA              GPIO ?  ─┬── EN    DEC    ← новый пин
         └─[10 кΩ]─ 3.3 В                   └─[10 кΩ]─ 3.3 В ← подтяжка, как у RA

Блок питания 12 В ──── VS обоих драйверов
ESP 3.3 В         ──── VCC_IO обоих драйверов
GND               ──── общий для ESP и обоих драйверов
```

### 3.2. Что купить и подключить

| Что | Кол-во |
|---|---|
| модуль TMC2209 (того же типа, что первый) | 1 |
| мотор NEMA 17 | 1 (или такой же, как первый) |
| резистор 10 кΩ (подтяжка EN) | 1 |
| провода | — |

### 3.3. Важно

- **Адрес задаётся пином MS1 второго модуля → 3.3 В.** На некоторых модулях
  MS1/MS2 выведены на перемычки — проверь по схеме модуля.
- То, что MS1/MS2 становятся адресом, **не влияет на микрошаг**: он у нас
  берётся из регистра (`GCONF.mstep_reg_select = 1`).
- **Свободные GPIO на ESP32-S3**: не брать strapping-пины (0, 3, 45, 46),
  пины USB (19, 20) и пины флеш-памяти/PSRAM (зависит от модуля — смотри
  распиновку своей платы). Уже заняты: 4, 5, 6, 12, 13, 17, 18.
- FastAccelStepper на ESP32-S3 поддерживает до 8 моторов (4 через MCPWM/PCNT
  + 4 через RMT) — два мотора без проблем.

### 3.4. Проверка железа (до кода)

1. Мультиметром: на MS1 второго модуля 3.3 В, на MS2 — 0 В.
2. На EN обоих модулей при выключенной ESP — 3.3 В (работает подтяжка).
3. Общая земля: прозвонить GND ESP ↔ GND обоих модулей.

## 4. Главная идея в коде: настройки оси

Сейчас настройки разбросаны по константам. Для двух осей их собирают
в **одну структуру на ось** — это и есть «каждая ось на своих настройках».

Новый файл `main/axis-config.h`:

```cpp
enum axis_t {
    AXIS_RA  = 0,
    AXIS_DEC = 1,
    AXIS_COUNT
};

struct axis_config_t {
    const char *name;          // "RA" / "DEC" — для логов

    // Железо
    uint8_t     uart_addr;     // 0 / 1 (пины MS1/MS2 модуля)
    gpio_num_t  en_pin;
    gpio_num_t  step_pin;
    gpio_num_t  dir_pin;

    // Драйвер
    uint8_t     irun;          // ток в движении, CS 0..31 (tmc_ma_to_cs)
    uint8_t     ihold;         // ток в покое
    uint8_t     irun_hot;      // пониженный ток при перегреве (otpw)
    uint8_t     pwm_grad;      // результат калибровки AT#2 (у каждого мотора свой)
    uint8_t     mres;          // микрошаг в CHOPCONF: 0 = 1/256, 2 = 1/64
    bool        shaft;         // инвертировать направление (GCONF.shaft)

    // Механика
    uint32_t    worm_teeth;    // 130 / 65 ⚠️ проверить
    uint32_t    belt_ratio;    // 1 (без ремня), 3, 4
    uint32_t    microsteps;    // 256 / 64 — должно совпадать с mres
};

extern const axis_config_t AXES[AXIS_COUNT];
```

Значения — в `axis-config.cpp`:

```cpp
// Порядок элементов = порядок в enum axis_t: сначала RA, потом DEC
const axis_config_t AXES[AXIS_COUNT] = {
    {   // AXIS_RA
        .name = "RA",  .uart_addr = 0,
        .en_pin = GPIO_NUM_6, .step_pin = GPIO_NUM_5, .dir_pin = GPIO_NUM_4,
        .irun = tmc_ma_to_cs(1050), .ihold = tmc_ma_to_cs(560), .pwm_grad = 51,
        .mres = 0, .shaft = false,
        .worm_teeth = 130, .belt_ratio = 1, .microsteps = 256,
    },
    {   // AXIS_DEC
        .name = "DEC", .uart_addr = 1,
        .en_pin = /* ? */, .step_pin = /* ? */, .dir_pin = /* ? */,
        .irun = tmc_ma_to_cs(1050), .ihold = tmc_ma_to_cs(560), .pwm_grad = 51 /* пока как у RA */,
        .mres = 0, .shaft = false,
        .worm_teeth = 65 /* ⚠️ */, .belt_ratio = 1, .microsteps = 256,
    },
};
```

> Две особенности C++:
> - поля в `{ .поле = ... }` нужно перечислять **строго в порядке объявления**
>   (с этим уже была ошибка сборки в `motion_cmd_t`);
> - запись `[AXIS_RA] = { ... }` (указать индекс массива) работает в C, но
>   **не в C++** — элементы массива пишутся по порядку, как в примере.

Производные величины (шагов на оборот оси, скорость ведения) удобно считать
функциями от конфига, а не держать отдельными константами:

```cpp
// шагов на полный оборот оси = 200 × микрошаг × червяк × ремень
uint64_t axis_steps_per_rev(axis_t a);

// скорость ведения в мГц = шагов на оборот / 86164.0905 с × 1000
uint32_t axis_sidereal_mhz(axis_t a);
```

На момент рефакторинга (без ремня, 1/256) для RA это 6 656 000 шагов и 77 248 мГц — после рефакторинга должны
получиться **те же числа** (проверка, что ничего не сломалось).

## 5. Шаг 1. Рефакторинг на одной оси

**Цель:** ввести понятие оси во весь код, но подключить **только RA**.
После шага всё должно работать **точно как сейчас**.

Делать по модулям, **собирать и проверять после каждого**.

### 5.1. `pins.h` ✅

- **Единственный источник пинов — `pins.h`**: там `RA_*_PIN`, `DEC_*_PIN`,
  UART. `AXES[]` в `axis-config.h` берёт пины оттуда.
- Код обращается к пинам через конфиг оси: `AXES[a].en_pin`,
  `AXES[a].step_pin`, `AXES[a].dir_pin` (пока везде `a = AXIS_RA`).
- Временные старые имена `ENABLE_PIN`, `STEP_PIN`, `DIR_PIN` удалены.

### 5.2. `tmc-uart` — адрес драйвера ✅

```cpp
// было
esp_err_t read_tmc_reg(uint8_t reg, uint32_t *value);
esp_err_t write_tmc_reg(uint8_t reg, uint32_t value);

// стало
esp_err_t read_tmc_reg(uint8_t addr, uint8_t reg, uint32_t *value);
esp_err_t write_tmc_reg(uint8_t addr, uint8_t reg, uint32_t value);
```

- В датаграмме байт `[1]` = `addr` вместо `UART_TMC_DRIVER_ADDR`.
- Чтение `IFCNT` внутри `write_tmc_reg` — тоже с этим адресом
  (счётчик у каждого драйвера свой).
- **Мьютекс остаётся один** — провод UART общий на оба драйвера, обмены
  по нему и так должны идти строго по очереди.
- Удобно сделать обёртки по оси, чтобы не писать везде `AXES[a].uart_addr`:

  ```cpp
  esp_err_t tmc_read(axis_t a, uint8_t reg, uint32_t *value);
  esp_err_t tmc_write(axis_t a, uint8_t reg, uint32_t value);
  ```

> Попутно исправить известную ошибку: `return` между `xSemaphoreTake`
> и `xSemaphoreGive` в `read_tmc_reg`/`write_tmc_reg` — ключ не отдаётся,
> UART может «замёрзнуть». Перед каждым таким `return` нужен `xSemaphoreGive`.

### 5.3. `tmc-driver` — все функции с параметром оси ✅

| Было | Стало | Что внутри меняется |
|---|---|---|
| `tmc_init_step_0()` … `tmc_init_step_11()` | `tmc_init_step_N(axis_t a)` | `read/write` → `tmc_read/tmc_write(a, …)`; пин EN — `AXES[a].en_pin` |
| шаг 4 (`GCONF`) | — | бит `shaft` из `AXES[a].shaft` |
| шаг 5 (`IHOLD_IRUN`) | — | `AXES[a].irun`, `AXES[a].ihold` вместо `TMC_IRUN`/`TMC_IHOLD` |
| шаг 7 (`PWMCONF`) | — | `AXES[a].pwm_grad` вместо `51UL` |
| шаг 11 (`CHOPCONF`) | — | `MRES` из `AXES[a].mres` |
| `tmc_driver_on()` / `tmc_driver_off()` | `(axis_t a)` | пин `AXES[a].en_pin` |
| `tmc_log_drv_status()`, `log_default_config()` | `(axis_t a)` | в логах имя оси `AXES[a].name` |
| `tmc_read_at_state(st)` | `(axis_t a, st)` | |
| `tmc_check_overheat()`, `tmc_overheat_reset()` | `(axis_t a)` | состояние перегрева — **массив на 2 оси** (`overheat_current_reduced[AXIS_COUNT]`, `overheat_last_hot_us[AXIS_COUNT]`); пониженный ток считать от `AXES[a].irun` |
| `monitor_log_task` | цикл по осям | имя оси в каждой строке лога |

- `tmc-current.h`: формулы (`tmc_ma_to_cs`, `tmc_cs_to_ma`) остаются общими
  (плата и резисторы одинаковые), а конкретные токи переезжают в `AXES[]`.
  `static_assert` на токи — **для каждой оси**.
- `initialize_tmc_driver()` → `initialize_tmc_driver(axis_t a)`, и переехать
  из `main.cpp` в `tmc-driver.cpp` (её зовут и `main`, и сторож).

### 5.4. `tmc-error` — сторож ✅

- `fault` → массив `fault[AXIS_COUNT]`, у каждой оси своё состояние аварии.
- Проверка одной оси вынесена в `watchdog_check_axis(axis_t a)`; задача
  вызывает её для каждой оси из `WATCHDOG_AXES[]` (пока только `AXIS_RA`).
- Тег лога с именем оси: `tmc-watchdog RA` / `tmc-watchdog DEC`.
- Политика «авария на одной оси → стоп обеих» и подключение DEC — на шаге 4.

### 5.5. `stepper` ✅

Сделано: массив `steppers[AXIS_COUNT]`, подключаются оси из `STEPPER_AXES[]`
(пока только RA); все функции движения с параметром оси; шаги на оборот мотора —
`axis_motor_steps_per_rev(a)`, скорость ведения — `axis_sidereal_mhz(AXIS_RA)`,
скорость/разгон наведения — `slew_speed_hz(a)` / `slew_accel(a)` в `stepper.cpp`
(от оборотов мотора оси). `motion.cpp` пока передаёт `AXIS_RA` (ось в команде — 5.6).


| Было | Стало |
|---|---|
| `static FastAccelStepper *stepper` | `static FastAccelStepper *steppers[AXIS_COUNT]` |
| `stepper_init()` | подключает **каждую** ось из `AXES[]` (`engine.init()` — один раз!) |
| `STEPS_PER_MOTOR_REV`, `SIDEREAL_SPEED_MHZ`, `SLEW_SPEED_HZ` | функции/поля от конфига оси |
| `stepper_emergency_stop()` | останавливает **все** оси (решение 1 из раздела 2) |
| `motion_blocked` | **один общий флаг** на обе оси (авария на любой блокирует обе) |
| `tmc_calibrate_at2(...)` | `(axis_t a, ...)` — калибровка каждой оси отдельно |

### 5.6. `motion` ✅

- В `motion_cmd_t` добавить поле `axis_t axis`.
- Порядок полей в структуре и в `{ .поле = ... }` — одинаковый.

### 5.7. Проверка после шага 1

- Сборка без ошибок и предупреждений.
- Лог `log_default_config` и шагов настройки — как раньше, с именем `RA`.
- Тест мотора RA: оборот туда-обратно, ведение — как раньше.
- Монитор: те же значения (`CS`, `GRAD_AUTO = 51`).
- Сторож: выдернуть питание — реакция как раньше.
- Посчитанные из конфига числа для RA: **6 656 000** шагов на оборот и
  **77 248 мГц** — совпадают со старыми константами.
  (После установки ремня 3:1 и микрошага 1/64 контрольные числа стали
  **4 992 000** и **57 936 мГц**, см. [belt-drive.md](belt-drive.md), раздел 9.)

## 6. Шаг 2. Связь со вторым драйвером

1. Подключить второй модуль по схеме из раздела 3 (мотор пока можно не
   подключать — но **питание VS обязательно**, без него драйвер не отвечает).
2. Прочитать `IOIN` по **адресу 1**:
   - версия `0x21` → связь есть;
   - нет ответа → проверить MS1 = 3.3 В, общий провод UART, питание VS.
3. Прочитать `IOIN` по **адресу 0** — RA должен по-прежнему отвечать
   (адреса не перепутаны, драйверы не мешают друг другу).
4. `log_default_config(AXIS_DEC)` — заводские значения второго модуля
   (проверить `internal_Rsense` и резисторы R_sense на втором модуле — если
   они **другие**, формула тока для DEC будет другой).

## 7. Шаг 3. Настройка и движение DEC

> **В коде сделано:** `initialize_tmc_driver(AXIS_DEC)` и `tmc_driver_on(AXIS_DEC)`
> в `app_main` (ошибка DEC не останавливает RA); DEC добавлен в `STEPPER_AXES`
> и `MONITOR_AXES`. В `app_main` закомментирована калибровка AT#2 для DEC. **Сторож DEC пока не проверяет — шаг 4.**

1. Заполнить `AXES[AXIS_DEC]`: пины, токи (по паспорту мотора DEC),
   зубья червяка, передача.
2. `initialize_tmc_driver(AXIS_DEC)` — шаги 0–11 для второго драйвера.
3. `tmc_driver_on(AXIS_DEC)` — ожидание 200 мс (AT#1).
4. Тест: оборот туда-обратно мотором DEC **без монтировки**.
5. **Калибровка AT#2 для DEC** (`tmc_calibrate_at2(AXIS_DEC, ...)`) — записать
   найденный `PWM_GRAD` в `AXES[AXIS_DEC].pwm_grad`. У DEC значение может
   отличаться от RA (другая нагрузка, возможно другой мотор/передача).
6. Направление: если DEC крутится не в ту сторону — `shaft = true` в конфиге.
7. Проверить, что RA при этом работает как раньше.

## 8. Шаг 4. Сторож на две оси

> **В коде сделано:** сторож проверяет оси, включённые через `tmc_watchdog_watch(a)`
> (в `app_main` — RA всегда, DEC только если настроен). Авария на любой оси →
> стоп всех осей и блокировка движения; выключение/перенастройка — только
> сломавшегося драйвера. Если не отвечают все драйверы — одно сообщение
> «пропало общее питание VS». Осталось проверить на железе (см. ниже).

Логика из [tmc-error.md](tmc-error.md) остаётся, но **на каждую ось своя**:

```
каждые 100 мс:
  для каждой оси a:
      прочитать GSTAT(a) → свой fault[a]
      новая авария на оси a → ОСТАНОВИТЬ ОБЕ ОСИ, выключить драйвер a (ENN_a = 1)
      reset на оси a        → перенастроить ТОЛЬКО драйвер a
      выход из аварии a     → включить ТОЛЬКО драйвер a
      нормальная работа     → tmc_check_overheat(a)
```

- `fault` → `static tmc_fault_t fault[AXIS_COUNT]`.
- Аварийная остановка — для обоих моторов (решение 1), а выключение и
  перенастройка драйвера — только для сломавшегося.
- Если **оба** драйвера не отвечают — скорее всего пропало общее питание VS.
- В логах — имя оси: `"АВАРИЯ [DEC]: перегрев…"`.
- Проверка: выдернуть VS (оба драйвера), затем отключить только UART-провод
  одного… (по возможности) — каждая ось обрабатывается правильно.

## 9. Шаг 5. Команды движения для двух осей

- `CMD_SLEW_RUN` с полем `axis` — команды двигают выбранную ось.
- Наведение на координаты — **обе оси одновременно**: две команды
  `stepper_move_to_async` (по одной на ось) запускаются без ожидания, затем ждать,
  пока обе доедут.
- Ведение — только RA; DEC при ведении стоит (держится током `IHOLD`).

## 11. Грабли

| Что | Почему опасно | Как избежать |
|---|---|---|
| перепутаны адреса | настройки RA уходят в драйвер DEC и наоборот | шаг 2: читать `IOIN` по обоим адресам; в логах всегда имя оси |
| `engine.init()` дважды | FastAccelStepper запускается один раз на все моторы | вызывать один раз, затем `stepperConnectToPin` для каждой оси |
| `return` внутри мьютекса UART | UART «замерзает» для обоих драйверов | исправить в шаге 1 (раздел 5.2) |
| общий `fault` или общий `overheat_current_reduced` | авария/перегрев одной оси путает обработку другой | массивы на `AXIS_COUNT` |
| порядок полей в `{ .поле = ... }` | ошибка сборки в C++ | перечислять в порядке объявления |
| разные модули TMC2209 | другие резисторы R_sense → другая формула тока | шаг 2, `log_default_config` + маркировка резисторов |
| DEC без проверки зубьев червяка | вдвое неверная скорость/позиция DEC | посчитать зубья до шага 3 |
| частые `reset` у DEC | драйвер сбрасывается к заводским настройкам, сторож перенастраивает его по кругу | VS/GND проводами прямо к модулю, конденсатор 100 мкФ, надёжный 3.3 В на VCC_IO/MS1 (см. tmc-error.md, 10.4) |
| стек задач | больше логов с двумя осями — больше стека | монитор логов: если будут перезагрузки с `stack overflow`, увеличить стек (сейчас 2048) |

## 12. Чек-лист

**Решения**
- ☑ Политика аварии: стоп всех осей, перенастройка только сломавшегося драйвера
- ☑ EN: свой пин на каждый драйвер
- ☐ Зубья червяка DEC посчитаны: ___ (в конфиге пока 65 ⚠️)
- ☑ Ремень 3:1 на обеих осях, микрошаг 1/64 — в конфиге ([belt-drive.md](belt-drive.md))
- ☑ Пины DEC выбраны: STEP 21, DIR 14, EN 16 (GPIO47/48 отвергнуты — см. esp32-pins.md)

**Шаг 1 — рефакторинг на одной оси**
- ☑ `axis-config.h`, таблица `AXES[]` (один заголовок, без `.cpp`), пины из `pins.h`
- ☑ `tmc-uart`: адрес в чтении/записи, обёртки `tmc_read/tmc_write`, исправлен `return` внутри мьютекса
- ☑ `tmc-driver`: все функции с осью, токи, `IRUN_HOT` и `PWM_GRAD` из конфига, перегрев на массивах
- ☑ `initialize_tmc_driver(axis)` переехала в `tmc-driver.cpp`
- ☑ `tmc-error`: `fault[AXIS_COUNT]`, проверка оси в `watchdog_check_axis(a)`
- ☑ `stepper`: массив моторов, функции с осью, константы из конфига
- ☑ `motion`: поле `axis` в команде
- ☑ 6 656 000 шагов / 77 248 мГц совпали (`static_assert`)

**Шаг 2 — связь**
- ☑ Второй модуль подключён, MS1 = 3.3 В
- ☑ `tmc_check_connection` для обоих адресов (не зависает без драйвера)
- ☐ `log_default_config(AXIS_DEC)`: проверить `internal_Rsense` и резисторы второго модуля

**Шаг 3 — DEC**
- ☐ Конфиг DEC заполнен (токи по паспорту мотора, зубья червяка)
- ☑ Настройка DEC при старте, мотор DEC подключён к FastAccelStepper, монитор DEC
- ☐ Калибровка AT#2 для DEC, `pwm_grad` записан в конфиг (после установки ремня — и для RA тоже)
- ☐ Направление DEC проверено (`shaft`)

**Шаг 4 — сторож**
- ☑ Аварии обрабатываются по осям, остановка всех, сторож только для настроенных осей
- ☑ Ограниченное ожидание в `tmc_init_step_1` — сторож не зависает при перенастройке
- ☐ Проверено выдёргиванием питания для двух осей
- ☐ Частые `reset` у DEC — найти плохой контакт / просадку питания

**Шаг 5 — движение**
- ☑ Команды с осью (`motion_cmd_t.axis`)
- ☐ Наведение двумя осями одновременно
