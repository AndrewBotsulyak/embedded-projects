# Алгоритм настройки TMC2209 по UART

Порядок работы с регистрами от подачи питания до движения мотора, а также
что делать при сбоях во время работы.

> **Источник:** [TMC2209.PDF](TMC2209.PDF), Rev. 1.03. Номера страниц даны
> в скобках, например (стр. 20).
> Значения из примеров: R_sense 0.11 Ω (проверено), мотор 42BYGH39-401AS (1.5 А),
> ток 1.05 А, микрошаг 1/256 (с установкой ремня 3:1 в коде **1/64**, см. шаги 7 и 12).
> **Актуальные значения в коде для каждой оси —
> в разделе [8](#8-реализация-в-коде-две-оси)** (токи и т.п. берутся из `AXES[]`).
> Кинематика EQ3-2 взята из соседнего проекта
> `eq3-2-got-to-set/info/technical-configurations.md`. Параметры, которые нужно
> подтвердить замером, помечены ⚠️.

## 1. Правила, которые влияют на порядок

Порядок настройки следует из нескольких свойств чипа, а не из номеров регистров.

| # | Свойство | Следствие для порядка |
|---|---|---|
| 1 | **Драйвер включён сразу после подачи питания.** В `CHOPCONF` по умолчанию `TOFF=3`, а это уже разрешение работы. Если `ENN` подключён к GND, ток идёт в обмотки с заводскими настройками (`IRUN=31`, масштаб от подстроечника VREF) ещё до того, как ESP начнёт обмен (стр. 29–31). | Сначала **выключить** драйвер (`TOFF=0`), в конце **включить**. |
| 2 | **Драйвер работает, только если `ENN=0` И `TOFF≠0`** (стр. 9, 31, 48). | Если EN подключён к ESP, держать `ENN=1` до конца настройки. Если EN подключён к GND, выключать драйвер через `TOFF=0`. |
| 3 | **Пин `PDN_UART` одновременно служит линией UART и входом снижения тока в покое.** В покое линия UART находится в высоком уровне, поэтому эта функция пина ломает логику тока (стр. 16). | Первым записывается `GCONF.pdn_disable=1`. |
| 4 | **`MRES` в `CHOPCONF` игнорируется, пока `GCONF.mstep_reg_select=0`**: микрошаг берётся с пинов MS1/MS2, а они у нас задают UART-адрес (стр. 20, 30). | `GCONF` записывается раньше `CHOPCONF`. |
| 5 | **`I_scale_analog` и `vsense` меняют значение `IRUN`/`IHOLD`** (стр. 50–51). | Токи считаются вместе с `vsense` и записываются до включения драйвера. |
| 6 | **Первый запуск StealthChop выполняет автотюнинг AT#1** в покое при токе `IRUN`, это ≥130 мс (стр. 35–36, 42). | `PWMCONF`, `IHOLD_IRUN` и `TPOWERDOWN` должны быть записаны **до** включения драйвера. |
| 7 | **Записываются только все 32 бита сразу.** Большинство регистров доступны только на запись (стр. 19). | Для каждого регистра хранить теневую копию в RAM и изменять поля в ней. |
| 8 | **У записи нет подтверждения**, есть только счётчик `IFCNT`, который увеличивается на 1 за каждую принятую запись (стр. 15, 21). | Сверять `IFCNT` до и после серии записей. |
| 9 | **После сброса питания драйвера все регистры возвращаются к заводским значениям**, и выставляется `GSTAT.reset` (стр. 21). | Весь алгоритм должен уметь выполняться повторно, а не только при старте. |

Доступ к регистрам (стр. 20–34): **RW** означает, что регистр можно прочитать
и проверить (`GCONF`, `CHOPCONF`, `PWMCONF`, `FACTORY_CONF`). **W** означает
только запись: такой регистр нельзя прочитать, можно лишь проверить `IFCNT`
(`IHOLD_IRUN`, `TPOWERDOWN`, `TPWMTHRS`, `TCOOLTHRS`, `VACTUAL`, `SGTHRS`,
`COOLCONF`, `SLAVECONF`). Для записи к адресу добавляется `0x80`.

## 2. Алгоритм кратко

```
Питание VS + VCC_IO
  │
  ├─ 0. [EN подключён к ESP] ENN = 1 (драйвер выключен)
  │
  ├─ 1. Связь       IOIN      → VERSION == 0x21?     иначе: повтор / ошибка проводки
  ├─ 2. Состояние   GSTAT     → запомнить, сбросить reset (записать 1)
  │                 IFCNT     → запомнить n0
  │                 (опц.) GCONF/CHOPCONF/PWMCONF/OTP_READ → лог значений из OTP
  ├─ 3. (опц.) SLAVECONF      → SENDDELAY, если не хватает времени на смену направления
  │
  ├─ 4. CHOPCONF   TOFF = 0   → драйвер выключен программно
  ├─ 5. GCONF                 → pdn_disable, mstep_reg_select, I_scale_analog=0, …
  ├─ 6. IHOLD_IRUN            → токи (vsense уже выбран)
  ├─ 7. TPOWERDOWN            → задержка до снижения тока (≥ 2)
  ├─ 8. PWMCONF               → StealthChop: autoscale, autograd, частота ШИМ
  ├─ 9. TPWMTHRS              → 0 (только StealthChop) или порог перехода на SpreadCycle
  ├─10. TCOOLTHRS, SGTHRS, COOLCONF = 0   → CoolStep/StallGuard выключены
  ├─11. VACTUAL = 0           → шаги идут с пина STEP (FastAccelStepper)
  ├─12. CHOPCONF   TOFF ≠ 0   → MRES, intpol, vsense, TBL, HSTRT/HEND. ДРАЙВЕР ВКЛЮЧЁН
  │
  ├─13. Проверка   IFCNT − n0 == число записей?
  │                GCONF, CHOPCONF, PWMCONF → совпадают с теневыми копиями?
  │                GSTAT == 0, DRV_STATUS без ошибок?
  │
  ├─14. [EN подключён к ESP] ENN = 0
  ├─15. AT#1: стоять ≥ 130 мс при токе IRUN (меньше TPOWERDOWN!)
  ├─16. AT#2: движение на средней скорости, несколько сотен полных шагов
  │
  └─ Рабочий режим: STEP/DIR + периодический опрос GSTAT/DRV_STATUS (раздел 5)
```

## 3. Шаги подробно

### Шаг 0. ENN: аппаратное выключение

Если EN подключён к GPIO ESP, настроить этот пин на выход с уровнем **1** как
можно раньше в `app_main`, а лучше ещё и поставить подтягивающий резистор к VCC_IO.
Тогда драйвер не подаёт ток в мотор, пока ESP загружается и настраивает регистры.

Если EN подключён к GND, пропустить этот шаг: выключение выполняется на шаге 4
через `TOFF=0`. Но от подачи питания до шага 4 мотор находится под заводским током
(см. правило 1).

### Шаг 1. IOIN (0x06): есть ли связь

Прочитать `IOIN` и проверить `VERSION` (биты 31..24) `== 0x21` (стр. 22).

- Ответа нет: драйвер ещё не получил питание (VCC_IO), неправильный адрес
  (MS1/MS2 = биты адреса 0/1, стр. 15), обрыв линии или нет резистора 1 кΩ
  между TX и линией (стр. 17).
- Ответ пришёл, но `VERSION` другая: на этом адресе стоит другой чип.

Повторять опрос с таймаутом: VS и VCC_IO могут появиться позже, чем
запустится ESP.

> Особенности UART (стр. 15–17): 8N1, скорость от 9000 бод до fCLK/16 = 750 кбод
> (115200 подходит). **Пауза длиннее 63 битовых интервалов посреди датаграммы
> сбрасывает приём**, поэтому датаграмму нужно отправлять одним `uart_write_bytes`.
> Линия однопроводная, поэтому в RX сначала приходят 4 байта эха собственного запроса,
> а за ними 8 байт ответа.

### Шаг 2. GSTAT (0x01) и IFCNT (0x02): стартовое состояние

1. Прочитать `GSTAT`. Бит `reset=1` при первом включении нормален.
   Если `drv_err=1` или `uv_cp=1` уже при старте, есть проблема с питанием
   или замыкание: записать это в лог.
2. Записать `GSTAT = 0x07`, чтобы **сбросить** все три флажка.
   С этого момента `reset=1` означает, что драйвер перезапустился **во время работы**.

   > **Почему единицы, а не нули.** `GSTAT` работает по правилу R+WC
   > (Write 1 to Clear): бит `1` в записи гасит флажок, бит `0` оставляет его
   > как есть. Зажечь флажок записью нельзя, это делает только сам драйвер.
   > Поэтому `0x07` (`111`) гасит всё, а `0x00` ничего не меняет.
   > Проверка: после записи чтение `GSTAT` должно вернуть `0x00`
   > (`drv_err` не погаснет, пока причина не устранена, а `uv_cp` гаснет сам,
   > когда питание в норме).
3. Прочитать `IFCNT`, запомнить как `n0`.

**Необязательно, но полезно для отладки:** прочитать `GCONF`, `CHOPCONF`,
`PWMCONF` и `OTP_READ (0x05)` и записать в лог. Там видны значения, которые
производитель модуля прошил в OTP (`internal_Rsense`, `en_spreadCycle`, `TBL`, …;
стр. 23–24). У разных модулей они могут отличаться.

### Шаг 3. SLAVECONF (0x03): задержка ответа (необязательно)

`SENDDELAY` (биты 11..8) задаёт, сколько драйвер ждёт перед ответом на чтение,
по умолчанию 8 битовых интервалов (стр. 21). Для ESP32 с резистором 1 кΩ обычно
хватает значения по умолчанию. Увеличивать нужно, только если первые байты ответа
теряются. Регистр влияет на все последующие чтения, поэтому его записывают
раньше остальных.

### Шаг 4. CHOPCONF (0x6C): выключить драйвер

Поменять в `CHOPCONF` только поле **`TOFF`** (биты 3..0) на 0, не трогая остальные биты:

1. Прочитать `CHOPCONF` (регистр читаемый). У нашего чипа после включения там `0x15010053`.
2. Обнулить младшие 4 бита: `value & ~0xF` → `0x15010050`.
3. Записать обратно.

Все силовые ключи закрыты, мотор свободен (стр. 31). Теперь можно менять
масштаб тока и режимы, не вызывая рывков тока.

> Не записывать «готовое» число из таблицы datasheet (`0x10000050`): реальное
> стартовое значение зависит от OTP и пинов MS1/MS2, и такая запись заодно
> изменила бы другие поля. Вреда не будет (на шаге 12 `CHOPCONF` перезаписывается
> целиком), но правило «меняй только то, что нужно» надёжнее.

> Если EN подключён к ESP и уже `ENN=1`, этот шаг можно пропустить,
> но он безвреден и защищает от ошибок в разводке.

### Шаг 5. GCONF (0x00): откуда чип берёт настройки

Первый содержательный регистр: он определяет, как будут пониматься все остальные.

| Бит | Поле | Значение | Почему |
|---|---|---|---|
| 0 | `I_scale_analog` | **0** | ток задают регистры, подстроечник VREF не влияет |
| 1 | `internal_Rsense` | **0** | на модуле стоят внешние резисторы R_sense ✅ (проверено: на плате два резистора R110, в OTP `internal_Rsense = 0`) |
| 2 | `en_spreadCycle` | **0** | StealthChop: тихо и плавно на скорости ведения |
| 3 | `shaft` | 0/1 | инвертировать направление без перепайки |
| 4 | `index_otpw` | 0 | |
| 5 | `index_step` | 0 | |
| 6 | `pdn_disable` | **1** | **обязательно при работе по UART** (стр. 16, 20) |
| 7 | `mstep_reg_select` | **1** | микрошаг из `MRES`, а не с пинов адреса |
| 8 | `multistep_filt` | 1 | заводское значение, фильтр входа STEP на высоких частотах |
| 9 | `test_mode` | **0** | заводской режим, всегда 0 |

**Итог: `GCONF = 0x000001C0`.** Регистр читаемый, поэтому после записи его
можно сверить чтением.

> ⚠️ Внимание, `internal_Rsense`: если на плате нет внешних резисторов, а бит
> равен 0 (или наоборот), ток будет совсем не тем, что рассчитан. Datasheet
> требует выставить этот бит **до включения мотора** (стр. 53).

### Шаг 6. IHOLD_IRUN (0x10): токи

Сначала рассчитать `IRUN` и `vsense` вместе (стр. 50):

```
I_RMS = (CS + 1)/32 × V_FS/(R_sense + 0.02 Ω) × 1/√2
V_FS = 0.325 В (vsense=0) или 0.180 В (vsense=1)
```

Правила выбора:
- `IRUN` в диапазоне **16…31**: ниже этого точность микрошага падает (стр. 25, 51).
  Для StealthChop допустимо не меньше 8 (стр. 39).
- Если `IRUN` получается меньше 16, поставить `vsense=1` и пересчитать.
  `vsense` записывается в `CHOPCONF` на шаге 12.
- `IHOLD`: 30–70% от `IRUN` (стр. 67). Проверить, что монтировка
  удерживает трубу.
- `IHOLDDELAY` 1…15: плавный переход к `IHOLD` без рывка. 0 означает переход скачком.
- **`IHOLD=0` не ставить**: при нуле включаются режимы свободного вращения
  и пассивного торможения из `PWMCONF.freewheel` (стр. 25, 43).

| Поле | Биты | Наш мотор 42BYGH39-401AS (1.5 А), R_sense 0.11 Ω |
|---|---|---|
| `IHOLD` | 4..0 | 10 → 336 мА при `vsense=1` (червяк держит ось сам) |
| `IRUN` | 12..8 | 22, при `vsense=1` → 702 мА (с ремнём 3:1 хватает; было 18 при `vsense=0` → 1049 мА) |
| `IHOLDDELAY` | 19..16 | 6 → ≈130 мс на ступеньку, спуск 18→9 (9 ступенек) ≈ 1.2 с |

**Итог: `IHOLD_IRUN = 0x0006160A`** (IRUN 22, IHOLD 10 при `vsense=1`; раньше было `0x00061209`). Регистр только на запись.

### Шаг 7. TPOWERDOWN (0x11): когда снижать ток

Задержка от обнаружения остановки (`stst`) до начала спада тока к `IHOLD`.
Единица равна 2¹⁸ тактов ≈ 21.8 мс при 12 МГц, диапазон 0…255 (≈0…5.6 с).

- **Минимум 2**, иначе не работает автотюнинг `PWM_OFS_AUTO` (стр. 25, 51).
- Значение должно быть больше длительности AT#1 (≥130 мс, то есть ≥ 6), иначе
  ток упадёт раньше, чем закончится тюнинг.
- Выбрано: **`TPOWERDOWN = 128`** ≈ 2.8 с. При коротких паузах ток не дёргается
  вниз-вверх, при долгой остановке плавно снижается до `IHOLD`.

> **Ведение и порог «мотор стоит».** Драйвер считает мотор остановленным, если
> шагов нет дольше 2²⁰ тактов ≈ **87 мс** (стр. 34, 62). Интервал между шагами
> при ведении RA (червяк 130 зубьев, мотор прямо на червяке, звёздные сутки 86164 с):
>
> | Микрошаг | Шагов/с | Интервал | Порог 87 мс |
> |---|---|---|---|
> | 1/16 | 4.8 | 207 мс | ❌ «стоит» после каждого шага |
> | 1/32 | 9.7 | 104 мс | ❌ |
> | 1/64 | 19.3 | 52 мс | ✅ |
> | 1/256 | 77.3 | 13 мс | ✅ большой запас |
> | **1/64 + ремень 3:1** | **57.9** | **17 мс** | ✅ (текущая механика) |
>
> Поэтому проблема решается не через `TPOWERDOWN`, а **выбором мелкого микрошага**.
> Без ремня было выбрано 1/256. С ремнём 3:1 (сейчас) шаги идут в 3 раза чаще,
> поэтому хватает **1/64** (шаг 12): во время ведения драйвер не уходит в «стоит»,
> ток всегда равен `IRUN`, а `TPOWERDOWN` влияет только на настоящие остановки.

### Шаг 8. PWMCONF (0x70): StealthChop

| Поле | Биты | Значение | Почему |
|---|---|---|---|
| `PWM_OFS` | 7..0 | 36 | стартовое значение для автотюнинга; после первого AT можно подставить `PWM_OFS_AUTO` |
| `PWM_GRAD` | 15..8 | 14 | стартовое значение (заводское у нашего чипа); после AT#2 подставить `PWM_GRAD_AUTO` |
| `pwm_freq` | 17..16 | **%01** | при 12 МГц это 35 кГц, в рекомендуемом диапазоне 20–50 кГц (стр. 37) |
| `pwm_autoscale` | 18 | **1** | автоматическая регулировка тока, рекомендуется datasheet (стр. 37) |
| `pwm_autograd` | 19 | **0** | **выключен**: `PWM_GRAD_AUTO` берётся прямо из `PWM_GRAD` (см. ниже) |
| `freewheel` | 21..20 | 0 | нужен только при `IHOLD=0` |
| `PWM_REG` | 27..24 | 8 | заводское у нашего чипа: подстройка успевает за разгоном; уменьшить, если ток «дёргается» |
| `PWM_LIM` | 31..28 | 12 | ограничение рывка при переходе SpreadCycle → StealthChop |

> **Почему `pwm_autograd = 0`.** Проверено на железе: при `pwm_autograd = 1`
> драйвер берёт стартовое `PWM_GRAD_AUTO` из OTP (14) **при включении питания**,
> и наша запись 51 в `PWM_GRAD` на него уже не влияет. Под нагрузкой монтировки
> автоподстройка до 51 не доходила → не хватало тока на скорости, мотор
> проскальзывал. С `pwm_autograd = 0` действует ровно `PWM_GRAD` из регистра.
> Значение 51 найдено калибровкой AT#2 (`tmc_calibrate_at2`) на 12 В; у каждой
> оси своё — `AXES[a].pwm_grad`.
>
> **В коде сейчас: `PWMCONF = 0xC8053324`** (OFS 36, GRAD 51, freq 1,
> autoscale 1, autograd 0, REG 8, LIM 12).

Справочно — заводское значение нашего чипа: `0xC80D0E24`, это значение, с которым стартует наш чип
(проверено чтением при пустой OTP). В таблице регистров datasheet указано
`0xC10D0024`, но реальный старт зависит от OTP (стр. 23–24): при `OTP_PWM_GRAD = 0`
получается `PWM_GRAD = 14`, при `otp_PWM_REG = 0` получается `PWM_REG = 8`.
Записывать всё равно явно, чтобы конфигурация не зависела от OTP модуля.

> ⚠️ **Нижний предел тока для автотюнинга** (стр. 39):
> `I_min = t_BLANK × f_PWM × V_M / R_coil`.
> При TBL=2 (32 такта), pwm_freq=%01: `I_min ≈ 0.094 × V_M / R_coil`.
> Для 12 В и 2 Ω это 0.56 А (1.05 А подходит). **Для 24 В и 2 Ω это 1.12 А, и 1.05 А
> уже ниже предела**: тогда уменьшить `TBL` до 1 или `pwm_freq` до %00.
> Подставь реальные V_M и R_coil своего мотора.

### Шаг 9. TPWMTHRS (0x13): граница StealthChop/SpreadCycle

- **`0`**: только StealthChop на всех скоростях. Рекомендуется для начала.
- Если на быстрой перекладке мотор теряет момент или резонирует: разогнаться
  до нужной скорости перехода, прочитать `TSTEP` (0x12) и записать это
  число в `TPWMTHRS` (стр. 42). Порог выбирать на низкой скорости, иначе при
  переключении режима будет рывок.

### Шаг 10. TCOOLTHRS (0x14), SGTHRS (0x40), COOLCONF (0x42): выключить

Записать `0` во все три регистра. CoolStep и StallGuard на скорости ведения
не работают надёжно, а концевиков через StallGuard в проекте нет. После сброса
они и так равны 0, но явная запись делает конфигурацию воспроизводимой.

### Шаг 11. VACTUAL (0x22): источник шагов

**`VACTUAL = 0`**: драйвер берёт шаги с пина STEP, их генерирует FastAccelStepper
(стр. 25). Ненулевое значение включает внутренний генератор шагов, и тогда
импульсы STEP игнорируются.

### Шаг 12. CHOPCONF (0x6C): микрошаг и включение драйвера

Записывается **последним**: ненулевой `TOFF` включает силовой каскад.

| Поле | Биты | Значение | Почему |
|---|---|---|---|
| `TOFF` | 3..0 | **5** | ≠0 включает драйвер; 3…5 подходит при 12 МГц (стр. 46, 67) |
| `HSTRT` | 6..4 | 4 | стартовое значение из Quick Guide (стр. 67) |
| `HEND` | 10..7 | 0 | в StealthChop не используются, влияют только на SpreadCycle |
| `TBL` | 16..15 | 2 (или 1) | см. предупреждение про I_min в шаге 8 |
| `vsense` | 17 | **1** | «малый диапазон»: максимум 978 мА, точность при 519..978 мА (`TMC_VSENSE` в `tmc-current.h`) |
| `MRES` | 27..24 | **2 = 1/64** (из `AXES[a].mres`) | 0=256, 1=128, **2=64**, 3=32, 4=16, 5=8, 6=4, 7=2, 8=полный шаг. Почему не крупнее, см. шаг 7 |
| `intpol` | 28 | 1 | интерполяция до 1/256 (MicroPlyer): драйвер дробит каждый шаг 1/64 на 4 микрошага 1/256 |
| `dedge` | 29 | 0 | несовместим с `multistep_filt` (стр. 30) |
| `diss2g`, `diss2vs` | 30, 31 | **0** | защита от короткого замыкания включена |

**Итог: `CHOPCONF = 0x12030045`** (`vsense = 1`; с `vsense = 0` было `0x12010045`, при `MRES = 0` без ремня — `0x10010045`).

> При 1/64 драйвер сам дробит каждый шаг до 1/256 (MicroPlyer), поэтому движение
> остаётся плавным. Интерполяция работает, пока шаги идут чаще ≈12 Гц: на ведении
> RA это 57.9 Гц, запас большой. (Для сравнения: при 1/16 без ремня ведение шло бы
> на 4.8 Гц, ниже порога, и каждый шаг был бы отдельным рывком; стр. 62.)
>
> Почему не оставили 1/256 с ремнём: мотору нужно в 3 раза больше импульсов на ту же
> скорость оси, и перекладка упёрлась бы в предел FastAccelStepper (200 000 шагов/с
> на ESP32-S3) уже на 3.6°/с.
>
> FastAccelStepper должен знать то же число шагов: `200 × 64 × 130 × 3` = 4 992 000
> на оборот RA, 13 867 на градус. Предел библиотеки 200 000 шагов/с ≈ 14.4°/с по RA.

### Шаг 13. Проверка

1. `IFCNT − n0` (по модулю 256) должен быть равен числу записей с шага 2.
   Если меньше, часть датаграмм потерялась: повторить настройку с шага 4.
2. Прочитать `GCONF`, `CHOPCONF`, `PWMCONF` и сравнить с теневыми копиями.
3. `GSTAT == 0`.
4. `DRV_STATUS (0x6F)`: нет `ot`, `s2ga/s2gb`, `s2vsa/s2vsb`. Флаги `ola/olb`
   в покое не проверять, они там ненадёжны (стр. 34, 66).

### Шаг 14. ENN = 0

Только если EN подключён к ESP. С этого момента мотор под током `IRUN`.

## 4. Автотюнинг StealthChop

Драйвер подстраивается под мотор сам, но для этого нужно выполнить два условия
(стр. 35–36).

### AT#1: определение PWM_OFS_AUTO

- Мотор **стоит**, ток равен **`IRUN`** (а не `IHOLD`), VS и VREF имеют рабочие уровни.
- Длительность ≤ 130 мс.
- Что делать: после шага 14 **подождать 150–200 мс, не подавая шагов**.
  Благодаря `TPOWERDOWN` ток ещё не успеет упасть до `IHOLD`.

### AT#2: определение PWM_GRAD_AUTO

- Мотор **движется** на скорости, при которой заметна противо-ЭДС: обычно
  60–300 об/мин. На скорости ведения этого не происходит.
- Требуется примерно 8 полных шагов на изменение значения на ±1, всего до ~400 полных шагов.
- Что делать: после старта сделать **калибровочное движение**, например
  качнуть ось туда и обратно на средней скорости или совместить его
  с первой перекладкой. Нужен участок постоянной скорости, а не только разгон.

### Сохранение результата

После AT#2 прочитать `PWM_AUTO (0x72)`: `PWM_OFS_AUTO` в битах 7..0,
`PWM_GRAD_AUTO` в битах 23..16. Сохранить в NVS и при следующем запуске
записать в `PWMCONF.PWM_OFS/PWM_GRAD` на шаге 8. Тогда тюнинг начнётся
почти с готовых значений (стр. 33). Прожигать их в OTP не нужно.

> **Изменение VS или VREF сбивает результат тюнинга** (стр. 36). После смены
> блока питания нужно снова выполнить AT#1 и AT#2.

## 5. Работа во время движения

### Периодический опрос (раз в 0.5–1 с и перед каждым движением)

```
GSTAT
 ├─ reset = 1   → драйвер перезапустился (просадка VCC_IO/VS)
 │                 все регистры заводские → остановить шаги,
 │                 повторить алгоритм с шага 0, затем AT#1
 │
 ├─ drv_err = 1 → прочитать DRV_STATUS, выяснить причину:
 │     ot / s2g* / s2vs* → остановить движение
 │                         выключить: TOFF=0 (или ENN=1)
 │                         устранить причину (остыть / проверить провода)
 │                         GSTAT ← 1 в drv_err, повторно включить: CHOPCONF с TOFF≠0
 │                         (флаги s2g/s2vs сбрасываются только выключением, стр. 34)
 │
 └─ uv_cp = 1   → низкое VS, драйвер выключен (флаг не защёлкивается)

DRV_STATUS
 ├─ otpw = 1    → перегрев (120 °C): уменьшить IRUN
 ├─ stst        → мотор стоит (полезно для отладки ведения)
 ├─ stealth     → в каком режиме чоппер сейчас
 └─ CS_ACTUAL   → текущий масштаб тока
```

### Изменение параметров на ходу

- **Ток** (`IHOLD_IRUN`) можно менять в любой момент, это безопасно.
- **Микрошаг** (`MRES`) можно менять на ходу (стр. 61), но **FastAccelStepper
  должен знать новое число шагов на оборот**, иначе позиция собьётся.
  Надёжнее менять его, когда мотор стоит.
- **`TPWMTHRS`** и напряжение VS не менять, пока драйвер находится
  в SpreadCycle выше порога (стр. 42).
- Любую запись выполнять через теневую копию: изменить поле в RAM
  и записать все 32 бита.

| Регистр | Почему |
|---|---|
| `OTP_PROG (0x04)` | прожиг OTP необратим: биты можно только установить, сбросить нельзя (стр. 23) |
| `FACTORY_CONF (0x07)`, поле `FCLKTRIM` | заводская калибровка генератора 12 МГц, у каждого чипа своя (стр. 22, 24) |
| `GCONF.test_mode` | заводской режим, пин ENN становится аналоговым выходом (стр. 20) |
| `CHOPCONF.diss2g/diss2vs` | отключает защиту от короткого замыкания |

## 8. Реализация в коде: две оси

Алгоритм выше выполняется **для каждой оси отдельно**: у RA и DEC свой драйвер
TMC2209 на общем проводе UART. План перехода — [two-axes.md](two-axes.md).

### 8.1. Откуда берутся значения

Все различия осей собраны в таблице `AXES[]` в `main/axis-config.h`; пины —
в `main/pins.h` (единственный источник номеров GPIO).

| Шаг алгоритма | Регистр | Поле конфига |
|---|---|---|
| 0, 14 | пин ENN | `AXES[a].en_pin` |
| все | адрес UART | `AXES[a].uart_addr` (задаётся пинами MS1/MS2 модуля) |
| 5 | `GCONF.shaft` | `AXES[a].shaft` |
| 6 | `IHOLD_IRUN` | `AXES[a].irun`, `AXES[a].ihold` |
| 8 | `PWMCONF.PWM_GRAD` | `AXES[a].pwm_grad` |
| 12 | `CHOPCONF.MRES` | `AXES[a].mres` |
| защита от перегрева | пониженный `IRUN` | `AXES[a].irun_hot` |

Проверки при сборке (`static_assert` в `axis-config.h`): токи в допустимых
пределах, микрошаг совпадает с `MRES`, адреса UART разные.

### 8.2. Текущие значения

| | RA | DEC |
|---|---|---|
| адрес UART | 0 (MS1 = GND, MS2 = GND) | 1 (MS1 = 3.3 В, MS2 = GND) |
| пины EN / STEP / DIR | 6 / 5 / 4 | 16 / 21 / 14 |
| `IRUN` | 25 → 1436 мА | 18 → 1049 мА ⚠️ по паспорту мотора DEC |
| `IHOLD` | 10 → 607 мА | 9 → 552 мА |
| `IRUN_HOT` (перегрев) | 16 → 943 мА | 16 → 943 мА |
| `PWM_GRAD` | 51 (калибровка на 12 В, без ремня) ⚠️ повторить AT#2 | 51 ⚠️ откалибровать отдельно |
| `IHOLD_IRUN` | `0x0006190A` | `0x00061209` |
| `PWMCONF` | `0xC8053324` | `0xC8053324` |
| микрошаг | 1/64 (`MRES = 2`) | 1/64 (`MRES = 2`) |
| `GCONF` / `CHOPCONF` | `0x000001C0` / `0x12010045` | то же (пока `shaft = 0`) |
| червяк | 130 | 65 ⚠️ посчитать зубья |
| ремень | 3 : 1 | 3 : 1 |

### 8.3. Функции

| Функция | Что делает |
|---|---|
| `tmc_read(a, reg, &v)` / `tmc_write(a, reg, v)` | чтение/запись регистра драйвера оси a (адрес из конфига, общий мьютекс UART) |
| `tmc_check_connection(a)` | проверка связи: версия чипа, уровни MS1/MS2/ENN; 5 попыток, **не зависает** |
| `initialize_tmc_driver(a)` | шаги 0–12 алгоритма по порядку |
| `tmc_driver_on(a)` / `tmc_driver_off(a)` | ENN = 0 (+ 200 мс на AT#1) / ENN = 1 |
| `log_default_config(a)` | заводские значения из OTP (до настройки) |
| `tmc_check_overheat(a)` | снижение тока при `otpw`, своё состояние у каждой оси |

### 8.4. Порядок запуска (`app_main`)

```
tmc_uart_init()
tmc_check_connection(RA), tmc_check_connection(DEC) → есть ли DEC
initialize_tmc_driver(RA)       ← повторяется, пока RA не ответит (ждём питание VS)
initialize_tmc_driver(DEC)      ← только если связь с DEC есть; ошибка DEC не останавливает RA
stepper_init()                  ← FastAccelStepper для RA и DEC
tmc_driver_on(RA), tmc_driver_on(DEC)
монитор, сторож (tmc_watchdog_watch: RA и DEC, если настроен)
```

### 8.5. Ожидание ответа на шаге 1

`tmc_init_step_1` ждёт ответа драйвера **~2 с** (20 попыток по 100 мс), а не
бесконечно, и возвращает `ESP_ERR_TIMEOUT`. Причина: функцию вызывает и сторож
при перенастройке, и бесконечное ожидание «заморозило» бы его для обеих осей.
Ожидание питания при старте сохранено: `app_main` повторяет настройку RA, пока
драйвер не ответит. Ошибка «ENN = 0 до настройки» теперь `ESP_ERR_INVALID_STATE`.
