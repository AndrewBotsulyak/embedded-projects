# ESP-NOW: связь монтировки с пультом

Как монтировка принимает команды LX200 от пульта по радио, как узнаёт MAC пульта
и что пока не сделано. Сторона пульта — [remote-control/info/pairing.md](../../remote-control/info/pairing.md)
и [espnow_link.md](../../remote-control/main/espnow_link/espnow_link.md).

---

## 1. Что это

ESP-NOW — протокол Espressif: пакеты до 250 байт напрямую от одной ESP32 к другой,
**без роутера и без подключения к Wi-Fi**. Wi-Fi включён только как радио.

По радио ходят обычные строки LX200 (`:Me#`, `:Qe#`, `:Te#`...) — тот же парсер,
что и для USB. ESP-NOW для монтировки — просто ещё один канал, как `lx200_usb`.

```
 ПУЛЬТ (ESP32-C3)                         МОНТИРОВКА (ESP32-S3)
 mount_link                               
   │ ":Me#"                               
   ▼                                      
 espnow_link ))) радио, канал 1 ))) ──►  on_recv (задача Wi-Fi) ──► rx_queue
                                                                       │
                                                                       ▼
                                                              lx200_espnow_task
                                                     ┌─────────────────┼──────────────────┐
                                                     ▼                 ▼                  ▼
                                               "?PAIR"           "?…" / "!…"         LX200 от своего пульта
                                            сопряжение           выбросить           lx200_feed() → motion
                                                     │                                    │
 espnow_link ◄──────────── "!PAIR" ─────────────────┘                                    │
 espnow_link ◄──────────── ответ команды (например "1") ─────────────────────────────────┘
```

## 3. Настройки (в `lx200_espnow.h`)

| Define | Значение | Что значит | Пульт (`espnow_link.h`) |
|---|---|---|---|
| `LX200_ESPNOW_CHANNEL` | 1 | канал Wi-Fi | `ESPNOW_LINK_CHANNEL` = 1 |
| `LX200_ESPNOW_PAIR_REQUEST` | `"?PAIR"` | пульт → все: «кто тут монтировка?» | `ESPNOW_PAIR_REQUEST` |
| `LX200_ESPNOW_PAIR_REPLY` | `"!PAIR"` | монтировка → пульт: «я» | `ESPNOW_PAIR_REPLY` |
| `LX200_ESPNOW_PAIR_WINDOW_MS` | 30000 | сколько после включения монтировка отвечает на `?PAIR` | — |

**Первые три должны совпадать с пультом.** Сейчас они записаны в двух местах —
меняя одно, поменять и другое (см. раздел 10).

## 4. Канал Wi-Fi

ESP-NOW работает на том канале, на котором стоит радио. Пакет на канале 1 плата
на канале 6 не услышит.

| | Пульт | Монтировка |
|---|---|---|
| Режим Wi-Fi | STA, без подключения | STA, без подключения |
| Канал | `esp_wifi_set_channel(1)` | `esp_wifi_set_channel(1)` |
| Канал peer | 1 (явно) | 0 = «текущий канал радио», то есть 1 |
| Энергосбережение | по умолчанию | выключено (`WIFI_PS_NONE`): радио слушает всё время |

Если позже монтировка подключится к роутеру, канал задаст роутер — тогда пульту
придётся перейти на тот же канал ([control-interfaces.md](control-interfaces.md)).

## 5. Сопряжение: как монтировка узнаёт MAC пульта

MAC не передаётся внутри сообщения: ESP-NOW сам сообщает адрес отправителя
(`src_addr` в колбэке приёма).

```
ПУЛЬТ  MENU → Link → Pair                       МОНТИРОВКА (включена < 30 с назад)
 │
 │ ?PAIR → FF:FF:FF:FF:FF:FF (всем)
 │ ────────────────────────────────────────►   src_addr = MAC пульта
 │ (повтор каждые 500 мс, до 10 с)             старый peer удалить, новый добавить
 │                                              MAC пульта → NVS
 │ ◄────────────────────────────────────────   !PAIR → лично пульту
 │ src_addr = MAC монтировки → NVS пульта
 │ экран: Link PAIRED
```

### Почему только первые 30 с

Без окна на `?PAIR` ответила бы **любая** такая монтировка рядом, и пульт взял бы
первую попавшуюся. Окно — это «режим сопряжения»: включил монтировку → в течение
30 с нажал Pair на пульте.

| Когда пришёл `?PAIR` | Что делает монтировка |
|---|---|
| меньше 30 с после включения | запоминает пульт (peer + NVS), отвечает `!PAIR` |
| позже | лог `?PAIR от … — режим сопряжения закончился`, не отвечает |

### Как сопрячь (по шагам)

1. Включить пульт.
2. Включить (или перезагрузить) монтировку.
3. В течение 30 с: на пульте **MENU → Link → Pair**.
4. На пульте `Link PAIRED`, в логе монтировки (COM) `сопряжено с пультом xx:xx:...`.

Новый пульт сопрягается так же: монтировка забывает старый и запоминает новый.

## 6. Приём пакетов

Задача `lx200_espnow_task` разбирает каждый пакет по порядку:

| Пришло | Что делает монтировка |
|---|---|
| ровно `?PAIR` | сопряжение (раздел 5) |
| начинается с `?` или `!` | выбросить: служебное, не для монтировки |
| LX200, пульт известен, MAC совпал | байты в `lx200_feed()`, ответ — пульту |
| LX200, пульт известен, MAC чужой | лог `пакет от чужого …`, выбросить |
| LX200, пульт неизвестен | этот отправитель становится пультом **до перезагрузки** (в NVS не пишется) |

LX200 всегда начинается с `:` или байта `0x06`, поэтому с `?PAIR`/`!PAIR` не путается.

В одном пакете может быть несколько команд — на каждую с ответом уходит отдельный пакет.

### Кто «пульт»

| Состояние | Откуда взялся | Переживает перезагрузку |
|---|---|---|
| нет пульта | NVS пуст, LX200 ещё не приходил | — |
| временный | первый, кто прислал LX200 | нет |
| сопряжённый | `?PAIR` в окне или NVS при старте | да |

## 7. Хранение MAC пульта

| | |
|---|---|
| Где | NVS, namespace `espnow`, ключ `remote_mac`, blob 6 байт |
| Когда пишется | `?PAIR` в окне сопряжения |
| Когда читается | `lx200_espnow_start()` при старте |
| Когда стирается | никогда (Unpair на пульте монтировку не трогает); перезапишется следующим сопряжением |

Пульт повторяет `?PAIR` раз в 500 мс, пока не получит `!PAIR`, поэтому при
сопряжении в NVS обычно 1–2 записи тех же 6 байт — для флеша это ничто.

## 8. Задачи и потоки

| Что | Где выполняется | Что делает |
|---|---|---|
| `on_recv` | задача Wi-Fi | только копия пакета в `rx_queue` (8 пакетов), без ожидания и логов |
| `on_send` | задача Wi-Fi | лог, если пульт не подтвердил приём |
| `lx200_espnow_task` | своя, приоритет 4, стек 4096 | сопряжение, фильтр, парсер LX200, ответы |
| `lx200_espnow_send()` | любая задача | отправить пульту; `ESP_ERR_INVALID_STATE`, если пульта нет |

MAC пульта меняет только `lx200_espnow_task`, а читает ещё `lx200_espnow_send()`
из других задач — поэтому MAC под спинлоком `remote_lock`.

### Порядок запуска (`app_main`)

```
stepper_init → … → lx200_usb_start → lx200_espnow_start
                                       │
                                       ├─ nvs_flash_init (Wi-Fi + MAC пульта)
                                       ├─ Wi-Fi STA, канал 1, без энергосбережения
                                       ├─ esp_now_init, колбэки
                                       ├─ MAC пульта из NVS → peer
                                       └─ задача lx200_espnow_task
```

`lx200_espnow_start()` — **после** `stepper_init()`: команды кладутся в очередь `motion_task`.
Ошибка запуска не останавливает программу: USB работает без радио.

lx200_espnow: пакет пульту не доставлен (…)

## 10. Ограничения и TODO

| Что | Почему важно | Сделано |
|---|---|---|
| **Защита от потери связи** | пульт повторяет `:M?#` каждые 200 мс; канал ESP-NOW помечает движение `keepalive`, и если повтора нет 500 мс, `motion_task` сама останавливает ось ([fsm.md](fsm.md), раздел 7) | ✅ |
| `nvs_flash_init` внутри модуля | пока NVS нужна только Wi-Fi и MAC пульта. Когда понадобится ещё где-то (например, `PWM_GRAD`) — перенести инициализацию NVS в `main` | ☐ |
| Константы в двух местах | канал и `?PAIR`/`!PAIR` записаны и в пульте, и в монтировке. Лучше вынести в общий компонент `components/` (как `lx200_format`) | ☐ |
| Шифрования нет | `encrypt = false`: кто знает протокол, может послать команду. Для дома и выезда достаточно | — |
| Место во флеше | с Wi-Fi прошивка ~0xD8BA0 байт, свободно ~15% раздела 1 МБ. Флеш 16 МБ — раздел можно увеличить | — |
| Монтировка не сообщает пульту своё состояние | пульт сам «заранее» меняет копию по своим командам | ☐ ([menu.md](../../remote-control/info/menu.md), раздел 9) |
