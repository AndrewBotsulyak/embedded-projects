# Логика команд: конечный автомат (FSM) монтировки

Как монтировка понимает команды от пульта, Stellarium и кнопок: какие у неё
состояния, как одна и та же команда работает в разных состояниях и где хранить
«режим» пульта. Это проект, в коде ещё не реализован.

Соседние документы: [control-interfaces.md](control-interfaces.md) — пульт,
компьютер, протокол LX200; [tmc-error.md](tmc-error.md) — аварии и сторож.

## 1. Где хранить состояние: монтировка или пульт

Монтировка физически всегда что-то делает: ведёт, едет, стоит или в аварии.
Это её состояние, и знать его должна она сама. Только на пульте его не удержать:

| Ситуация | Почему пульту не справиться |
|---|---|
| GoTo закончилось | событие происходит **на монтировке**: пульт не знает момент, когда включить ведение |
| Управляют двое: пульт и Stellarium | у каждого было бы своё представление о режиме, и они разошлись бы |
| Пропала связь с пультом | монтировка должна сама остановить ручное движение, не зная режима пульта |
| Авария (сторож) | её видит только монтировка |
| Отпустил кнопку при правке во время ведения | вернуться надо **к скорости ведения**, а не к нулю, а это зависит от того, включено ли ведение |

**Решение — разделить ответственность:**

```
ПУЛЬТ (режим интерфейса)                      МОНТИРОВКА (состояние движения)
─────────────────────────                      ───────────────────────────────
«Режим: правка / поиск / перекладка»           IDLE / TRACKING / GOTO / PARKED / FAULT
«Выбранный объект в меню»                      + ручное движение по каждой оси
кнопки → простые команды:                      решает, ЧТО значит команда в текущем
  «скорость = правка», «вперёд по RA»,         состоянии
  «стоп по RA», «GoTo на (RA, DEC)»
```

Монтировка не знает, что такое «режим правки» на пульте. Она знает только
«выбрана скорость GUIDE» и «ось RA едет на запад».

Так устроен и протокол LX200: пульт задаёт **скорость** (`:RG#` правка,
`:RC#` центрирование, `:RM#` поиск, `:RS#` перекладка) и **направление**
(`:Me#` поехать, `:Qe#` стоп), а монтировка сама вычисляет итоговую скорость мотора.

## 2. Правка в режиме ведения — не отдельное состояние

Правка — это **ведение плюс добавка**. Пример при скорости правки 0.5× звёздной:

```
ось RA, ведение:              57.9 Гц  (1× звёздной)
  нажал «на запад»   → 1 + 0.5 = 1.5×  →  86.9 Гц
  нажал «на восток»  → 1 − 0.5 = 0.5×  →  29.0 Гц
  отпустил           → 1×              →  57.9 Гц   ← назад к ведению, а не к нулю!

ось DEC (ведения нет):
  нажал «на север»   → 0.5×            →  14.5 Гц  (у DEC червяк 65: импульсов в 2 раза меньше)
  отпустил           → стоп
```

Поэтому состояние хранится в двух частях:
- **состояние монтировки** — одно на всю монтировку: ведём ли, идёт ли GoTo;
- **ручное движение** — отдельно для каждой оси: направление и скорость.

Можно одновременно жать «север» и «запад», а ведение по RA продолжается.

## 3. Состояния монтировки

| Состояние | Что происходит |
|---|---|
| `IDLE` | моторы стоят, ведения нет |
| `TRACKING` | ось RA ведёт со звёздной скоростью |
| `GOTO` | обе оси едут к цели |
| `PARKED` | в позиции парковки, команды движения игнорируются, кроме «распарковать» |
| `FAULT` | авария, движение заблокировано (сторож) |

Ручное движение по осям **не меняет** `IDLE` и `TRACKING`: это надстройка над ними.

```
                 TRACK ON                    GOTO(цель)
      ┌──────┐ ─────────────► ┌──────────┐ ─────────────► ┌──────┐
      │ IDLE │                │ TRACKING │                │ GOTO │
      └──────┘ ◄───────────── └──────────┘ ◄───────────── └──────┘
        ▲  ▲    TRACK OFF /        ▲          GOTO_DONE      │ │
        │  │    ABORT              │                         │ │ ABORT
        │  └───────────────────────┼─────────────────────────┘ │
        │      GOTO(цель) из IDLE ─┼───────────────────────────┘
        │                          │
        │  FAULT снят      ┌───────┴──┐
        └──────────────────│  FAULT   │ ◄── FAULT из любого состояния
                           └──────────┘

      PARKED: вход по команде PARK (после GoTo в позицию парковки), выход — UNPARK → IDLE
```

## 4. Таблица переходов

| Состояние \ Событие | MOVE(ось, направление) | STOP(ось) | GOTO(цель) | TRACK ON/OFF | GOTO_DONE (внутреннее) | ABORT `:Q#` | FAULT | FAULT снят |
|---|---|---|---|---|---|---|---|---|
| **IDLE** | ось едет с выбранной скоростью | ось стоп | → `GOTO` | ON → `TRACKING` | — | все стоп | → `FAULT` | — |
| **TRACKING** | ось: ведение ± скорость | RA: назад к ведению; DEC: стоп | → `GOTO` | OFF → `IDLE` | — | все стоп → `IDLE` | → `FAULT` | — |
| **GOTO** | **игнорировать** (или прервать GoTo — см. раздел 8) | — | новая цель | — | → `TRACKING` | стоп → `IDLE` | → `FAULT` | — |
| **PARKED** | игнор | — | игнор | игнор | — | — | → `FAULT` | — |
| **FAULT** | отказ | — | отказ | отказ | — | — | — | → `IDLE` |

Зачем таблица: она показывает решения, которые без FSM разошлись бы по `if`-ам
в разных местах:
- что делать, если во время GoTo нажали стрелку;
- включается ли ведение после GoTo;
- куда возвращаться после аварии. Сейчас после аварии ведение выключено
  (лог сторожа «Ведение остановлено, запустить снова»), то есть переход в `IDLE`.

Одна и та же команда значит разное в разных состояниях: `STOP` по RA в `IDLE`
означает «стоп», а в `TRACKING` — «вернуться к ведению». Поэтому «просто
реагировать на команды» без состояния не получится.

## 5. Скорости ручного движения

Скорость выбирает пульт командой `CMD_SET_RATE`, монтировка её запоминает.
Значения — в долях звёздной скорости своей оси (для RA: 1× = 57.936 Гц при 1/64,
ремне 3:1 и червяке 130; цифры по обеим осям — [commands.md](commands.md), раздел 2).

| Скорость | LX200 | Пример | Для чего |
|---|---|---|---|
| `GUIDE` | `:RG#` | 0.5× | правка во время ведения, гидирование |
| `CENTER` | `:RC#` | 8× | центрирование объекта в окуляре |
| `FIND` | `:RM#` | 64× | поиск в искателе |
| `SLEW` | `:RS#` | максимум (сейчас `slew_speed_hz`: 25 600 Гц ≈ 442× для RA) | перекладка |

Итоговая скорость оси:

| Ось | Состояние | Скорость мотора |
|---|---|---|
| RA | `TRACKING` | `звёздная × (1 ± rate)` (знак зависит от направления) |
| RA | `IDLE` | `звёздная × rate` |
| DEC | любое | `звёздная × rate` |

Если при `TRACKING` выбрана скорость `rate > 1` и направление против ведения,
`1 − rate` становится отрицательным: ось едет в обратную сторону. Это нормально,
FastAccelStepper просто меняет направление.

## 6. Как это ложится в код

`motion_task` ([motion.cpp](../main/stepper/motion.cpp)) уже единственная задача,
которая двигает моторы, поэтому FSM живёт в ней. Внутренние события
(«доехал», «авария») приходят в ту же очередь, что и команды:

```
источники (пульт, Stellarium) ──────────► motion_send(команда)    ──┐
FastAccelStepper: «доехал» ─────────────► motion_send(GOTO_DONE)  ──┼──► motion_task:
сторож: авария / снята ─────────────────► motion_send(FAULT ...)  ──┘      switch (state) {
                                                                             case IDLE: ...
                                                                             case TRACKING: ...
                                                                           }
```

Библиотека не нужна: `enum` состояний + `switch`, как в стороже
(`switch (fault[a])` в [tmc-error.cpp](../main/tmc-driver/tmc-error.cpp)).
Таблица из раздела 4 — документация, а в коде достаточно `switch`.

Команды становятся **общими**, без слова «режим»:

```cpp
enum e_motion_cmd_t {
    CMD_SET_RATE,     // скорость ручного движения: GUIDE / CENTER / FIND / SLEW
    CMD_MOVE,         // ось + направление: ехать, пока не придёт CMD_STOP
    CMD_STOP,         // ось: прекратить ручное движение
    CMD_GOTO,         // цель (шаги или RA/DEC)
    CMD_TRACK,        // вкл/выкл ведение
    CMD_ABORT,        // стоп всего (:Q#)
    CMD_PARK,         // уехать в позицию парковки → PARKED
    CMD_UNPARK,       // PARKED → IDLE
    // внутренние события
    EVT_GOTO_DONE,    // GoTo закончилось (проверка isRunning обеих осей)
    EVT_FAULT,        // сторож: авария
    EVT_FAULT_CLEARED,// сторож: все оси в норме, движение разрешено
};

enum e_mount_state_t {
    MOUNT_IDLE,
    MOUNT_TRACKING,
    MOUNT_GOTO,
    MOUNT_PARKED,
    MOUNT_FAULT,
};
```

Состояние ручного движения по осям:

```cpp
typedef struct {
    bool    moving;      // кнопка нажата (пришёл CMD_MOVE, ещё не было CMD_STOP)
    bool    forward;     // направление
    int64_t last_move_us;// когда последний раз пришёл CMD_MOVE (для раздела 7)
} axis_manual_t;
```

**Связь со сторожем.** Сейчас сторож сам вызывает `stepper_emergency_stop()` и
`stepper_unblock()`. Это остаётся: аварийная остановка должна сработать сразу,
не дожидаясь очереди. Дополнительно сторож отправляет `EVT_FAULT` и
`EVT_FAULT_CLEARED` в очередь, чтобы FSM узнала об аварии и сменила состояние.

**Как узнать, что GoTo закончилось.** FastAccelStepper не присылает событие.
Варианты: `motion_task` ждёт очередь с таймаутом (например, 50 мс) и
по таймауту проверяет `isRunning()` обеих осей, а в состоянии `GOTO` при
остановке обеих порождает `EVT_GOTO_DONE`.

## 7. Защита от потери связи с пультом

Пока кнопка нажата, пульт **повторяет** команду `CMD_MOVE`, например раз
в 200 мс. Монтировка запоминает время последнего повтора (`last_move_us`).
Если повтора не было дольше ~500 мс, монтировка сама делает `CMD_STOP` по этой оси.

```
пульт:       MOVE ── MOVE ── MOVE ── ✕ (связь пропала)
монтировка:  едет    едет    едет    ... 500 мс без MOVE → STOP
```

Без этого при пропаже связи посреди нажатия ось уедет до упора.

Проводные источники (USB) могут не повторять команду. Тогда
для них таймаут отключается (например, флагом источника в команде).

**Как сделано** ([motion.cpp](../main/stepper/motion.cpp)):

| Где | Что |
|---|---|
| `motion_cmd_t.keepalive` | `true` — источник повторяет `CMD_MOVE`. Ставит только канал ESP-NOW (`lx200_ctx_t.keepalive_moves`); USB — `false`, таймаута нет |
| `CMD_MOVE` | запоминает `last_move_us`. Ось уже едет туда же — это повтор: только время, без `apply_axis()` и логов motion |
| `poll()` (раз в 50 мс) | ось едет, `keepalive`, повтора нет дольше `MOTION_KEEPALIVE_MS` (500) → стоп оси, как `CMD_STOP` (RA при ведении — к ведению) |

Цепочка: `lx200_espnow` (`ctx.keepalive_moves = true`) → `cmd_move` → `mount_move(dir, keepalive)`
→ `motion_move(axis, forward, keepalive)`. Ось встаёт через 500–550 мс после последнего повтора.
Последняя команда решает: `:Mw#` с USB после пульта снимает таймаут с этой оси.

## 8. Решения и что уже сделано

Реализовано в [motion.cpp](../main/stepper/motion.cpp): состояния `IDLE`,
`TRACKING`, `GOTO`, `FAULT` и команды `CMD_SET_RATE`, `CMD_MOVE`, `CMD_STOP`,
`CMD_TRACK`, `CMD_GOTO`, `CMD_ABORT`. Отправлять — функциями `motion_move()`,
`motion_stop()`, `motion_set_rate()`, `motion_track()`, `motion_goto()`, `motion_abort()`.

| Вопрос | Решение |
|---|---|
| Стрелка во время GoTo | **прерывает GoTo** → `TRACKING`, дальше ручное движение |
| Ведение после GoTo | включается **всегда** (и после прерванного стрелкой GoTo) |
| Выход из аварии | в `IDLE`, ведение не возобновляется: позиция могла сбиться |
| Скорости | `GUIDE` 0.5×, `CENTER` 8×, `FIND` 64×, `SLEW` — скорость перекладки |
| Как FSM узнаёт об аварии | `motion_task` раз в 50 мс смотрит `stepper_is_blocked()`: сторож отдельных событий не шлёт |

Ещё не сделано:
- `PARKED` (нет парковки);
- полный **источник команды** (пульт, Stellarium) в `motion_cmd_t` — пока
  только флаг `keepalive` для таймаута из раздела 7.
