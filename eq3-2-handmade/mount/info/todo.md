## 1. Мьютекс для UART драйвера

**Когда понадобится:** как только появится задача-сторож (периодическая проверка
`GSTAT`), то есть когда к драйверу по UART будут обращаться из двух мест.

**Проблема.** Если задача-сторож и основной код обращаются к драйверу по UART
одновременно, их датаграммы перемешаются:

```
основной код:  05 00 EC ── ── 14 01 00 45 CRC        (запись CHOPCONF)
сторож:                 05 00 01 CRC                 (чтение GSTAT) влезло в середину
на проводе:    05 00 EC 05 00 01 CRC 14 01 ...       ← драйвер получил мусор
```

Драйвер отбросит испорченную датаграмму (не сойдётся CRC), и команда потеряется.

**Что такое мьютекс.** Это «ключ от UART», который в каждый момент может держать
только одна задача. Задача берёт ключ, делает обмен целиком (запрос + ответ) и
возвращает ключ. Если в это время ключ нужен другой задаче, она ждёт, пока его
вернут. Так обмены идут строго по очереди и не перемешиваются.

**Как сделать:**

```cpp
#include "freertos/semphr.h"

static SemaphoreHandle_t tmc_uart_mutex;

// один раз, в tmc_uart_init():
tmc_uart_mutex = xSemaphoreCreateMutex();

// в read_tmc_reg() и в функции записи регистра:
esp_err_t read_tmc_reg(uint8_t reg, uint32_t *value) {
    xSemaphoreTake(tmc_uart_mutex, portMAX_DELAY);   // взять ключ (ждать, если занят)
    // ... отправка запроса и приём ответа ...
    xSemaphoreGive(tmc_uart_mutex);                  // вернуть ключ
    return ESP_OK;
}
```

**Важно:** ключ нужно вернуть на **каждом** выходе из функции, в том числе при
ошибке (`return ESP_ERR_...`). Если забыть, ключ останется «занятым» навсегда,
и все остальные обращения к драйверу повиснут.

## 2. Проверка GSTAT перед началом движения

**Когда понадобится:** когда дойдёт до перекладки (быстрых перемещений).

**Проблема.** Сторож проверяет `GSTAT` раз в секунду, поэтому между проверками
есть «слепое окно» до 1 секунды:

```
время:    0с          1с          2с
сторож:   проверил ✅ проверил ✅ проверил ❌ reset!
                        │
драйвер:                │  ← тут перезагрузился (просело питание)
                        │
команда:                │   «перекладка» стартует с заводскими настройками
```

Если драйвер перезагрузился в этом окне, он работает с заводскими настройками:
микрошаг берётся с пинов MS1/MS2 (у RA оба на земле, это **1/8** вместо
настроенных 1/64). FastAccelStepper этого не знает, и мотор крутится **в 8 раз
быстрее**. Телескоп уедет не туда, а сторож заметит это уже после старта.

**Как сделать:** перед запуском любого движения прочитать `GSTAT` ещё раз, не
дожидаясь сторожа. Одно чтение занимает около 1 мс.

```cpp
void slew_to(int32_t target)
{
    uint32_t gstat;
    if (read_tmc_reg(TMC_REG_GSTAT, &gstat) != ESP_OK || gstat != 0) {
        // драйвер не отвечает или что-то случилось: сначала разобраться
        return;
    }
    stepper->moveTo(target);   // только теперь едем
}
```

Не срочно: перезагрузка драйвера случается редко (плохой контакт, просадка блока
питания), для начала хватит сторожа раз в секунду.

## 3. Определение упора шагового двигателя

**Задача:** найти способ определять, что ось монтировки упёрлась (в штатив,
кабель и т. п.), и сразу останавливать мотор.

**Что уже известно:**

- **На перекладке** можно использовать StallGuard драйвера: он оценивает
  нагрузку (`SG_RESULT`, 0x41) и при упоре даёт импульс на пин **DIAG**.
  Нужно: провод DIAG → GPIO ESP, `TCOOLTHRS` (≈234 для 1 об/с мотора; от микрошага не зависит —
  драйвер считает `TSTEP` в единицах 1/256),
  подбор `SGTHRS` опытом на живой монтировке, остановка мотора по прерыванию.
  Работает только в StealthChop (`TPWMTHRS = 0`).
- **Ограничение:** StallGuard ненадёжен ниже ~1 оборота мотора в секунду
  (datasheet стр. 56), это ≈2.8°/с по RA. Перекладка должна быть быстрее ~3°/с.
- **На ведении** (0.0015 об/с = 0.09 об/мин) драйвером упор не определить. Нужен отдельный
  способ, например энкодер на оси.

## 4. Сохранение PWM_GRAD в NVS (калибровка AT#2)

**Когда понадобится:** когда дойдёт до перекладки. Для ведения не нужно.

**Суть.** Автоподстройка StealthChop состоит из двух частей:

```
напряжение = PWM_OFS  +  PWM_GRAD × скорость
             └─ AT#1 ─┘  └──────── AT#2 ────────┘
```

- **AT#1** драйвер делает сам при каждом включении, нужно только подождать
  ~200 мс после `ENN = 0`, не подавая шагов. Для ведения этого достаточно.
- **AT#2** идёт во время движения на средней скорости (60–300 об/мин мотора,
  то есть перекладка быстрее ~3°/с по RA). На ведении (0.09 об/мин) добавка
  `PWM_GRAD × скорость` ≈ 0, поэтому там AT#2 не нужен. На перекладке
  неподобранный `PWM_GRAD` может дать недостаток тока и пропуск шагов.
- Найденное значение теряется при выключении питания.

**Что сделать:**

1. Первый запуск: после перекладки прочитать `PWM_AUTO` (0x72), взять
   `PWM_GRAD_AUTO` (биты 23..16) и сохранить в NVS (флеш-память ESP).
2. Каждый запуск: достать значение из NVS и записать в `PWMCONF.PWM_GRAD`
   вместо стартового 14 (шаг 8 алгоритма / `tmc_init_step_7`).
3. Писать в NVS, только если значение изменилось (ресурс флеш-памяти).
4. При смене мотора или блока питания сохранённое значение сбросить.

## 5. ESP-NOW: принимать команды только от сопряжённого пульта

**Когда понадобится:** когда закончится отладка пульта по ESP-NOW.

**Проблема.** `accept_sender()` в `main/lx200/lx200_espnow.cpp`:

```cpp
static bool accept_sender(const uint8_t *mac) {
    if (remote_known) {               // пульт известен → принять, только если это он
        return is_remote(mac);
    }
    return set_remote(mac) == ESP_OK; // пульт неизвестен → сделать пультом ЭТОГО отправителя
}
```

Если монтировка ещё не сопряжена (в NVS пусто), то пультом становится **первый**,
кто пришлёт LX200-команду, без всякого `?PAIR`. Этот адрес не сохраняется в NVS
и живёт до перезагрузки.

```
монтировка свежая (NVS пуст), рядом чужое ESP-NOW-устройство
шлёт ":Ms#" на MAC монтировки
→ accept_sender → remote_known = false → оно становится «пультом»
→ настоящий пульт отбрасывается как «чужой» до перезагрузки
```

Окно сопряжения (30 с) тут не помогает: эта ветка работает всегда, пока пульт
неизвестен. Случайно это бывает редко (чужое устройство должно знать MAC
монтировки и стоять на том же канале), но возможно.

**Как сделать:** убрать ветку «пульт неизвестен», принимать только `?PAIR`:

```cpp
static bool accept_sender(const uint8_t *mac) {
    return is_remote(mac);   // is_remote уже проверяет remote_known
}
```

Тогда несопряжённая монтировка выбрасывает все LX200-команды, пока не пройдёт
`?PAIR` в первые 30 с после включения.
