# espnow_link — радиосвязь ESP-NOW

## Какую задачу решает

Пульт и монтировка — две платы ESP32 без провода между ними. ESP-NOW — протокол
Espressif: пакеты до 250 байт напрямую от платы к плате, **без роутера и без подключения
к Wi-Fi**. Модуль запускает радио, отправляет и принимает пакеты.

Модуль **ничего не знает про LX200**: он передаёт байты как есть. Что отправлять,
решает `mount_link`. Модуль знает только **кому** отправлять: MAC монтировки
(сопряжение, раздел ниже).

```
mount_link: espnow_link_send(":Me#") ── TX ──────►┐
колбэк Wi-Fi «пакет пришёл»          ── RX ──────►┼──► очередь ──► task_espnow_link
меню: pair_start / unpair            ── PAIR ────►│                    │
колбэк Wi-Fi «пакет отправлен»       ── TX_DONE ─►┘                    │
                                                         ┌─────────────┼────────────────┐
                                                         ▼             ▼                ▼
                                                   esp_now_send()   лог «не дошло»   RX → очереди подписчиков
```

## Файлы

| Файл | Что внутри |
|---|---|
| `espnow_link.h` | канал, MAC монтировки, `espnow_packet_t`, API |
| `espnow_link.cpp` | запуск Wi-Fi и ESP-NOW, колбэки, очередь событий, задача |

## Настройки (в `espnow_link.h`)

| Define | Значение | Что значит |
|---|---|---|
| `ESPNOW_LINK_CHANNEL` | 1 | канал Wi-Fi. **У пульта и монтировки должен совпадать** |
| `ESPNOW_PAIR_REQUEST` / `ESPNOW_PAIR_REPLY` | `"?PAIR"` / `"!PAIR"` | служебные сообщения сопряжения |
| `ESPNOW_PAIR_REQUEST_MS` | 500 | как часто повторять `?PAIR` при поиске |
| `ESPNOW_PAIR_TIMEOUT_MS` | 10000 | сколько искать |
| `ESPNOW_LINK_MAX_DATA` | 250 | максимум байт в одном пакете (ограничение ESP-NOW v1) |

## MAC монтировки: сопряжение

MAC не зашит в код: пульт узнаёт его командой **MENU → Link → Pair** и хранит в NVS.
Полная логика — в [info/pairing.md](../../info/pairing.md).

| Состояние | Куда уходят команды | От кого принимаем |
|---|---|---|
| `NOT_PAIRED` | broadcast `FF:FF:FF:FF:FF:FF`, без подтверждения доставки | от всех |
| `PAIRING` | как было до поиска; раз в 500 мс `?PAIR` всем | ждём `!PAIR` |
| `PAIRED` | только монтировке, с подтверждением | только от монтировки |

Broadcast-peer добавлен всегда: через него идёт поиск. Peer монтировки добавляется,
когда она найдена (или прочитана из NVS при старте), и удаляется по Unpair.

MAC своей платы модуль пишет в лог при старте:

```
ESPNOW: this board MAC 34:85:18:aa:bb:cc, channel 1
ESPNOW: mount from NVS: 34:85:18:11:22:33          ← или "not paired: ..."
```

## Функции

| Функция | Что делает |
|---|---|
| `espnow_link_init()` | NVS → Wi-Fi (только радио, STA) → канал → ESP-NOW → колбэки → broadcast-peer → MAC из NVS → задача |
| `espnow_link_send(data, len)` | положить пакет в очередь задачи (ждёт не дольше 50 мс) и вернуться |
| `espnow_link_subscribe_rx(queue)` | очередь `espnow_packet_t` для принятых пакетов (кроме служебных) |
| `espnow_link_subscribe_state(queue)` | очередь `screen_msg_t` для `SCREEN_MSG_LINK_CHANGED` |
| `espnow_link_pair_start()` | начать поиск монтировки |
| `espnow_link_unpair()` | забыть монтировку: стереть NVS, удалить peer, broadcast |
| `espnow_link_get_state()` | `NOT_PAIRED` / `PAIRING` / `PAIRED` (из любой задачи) |
| `espnow_link_get_peer(mac)` | MAC монтировки; `false` — не сопряжены (из любой задачи, под спинлоком) |

## Почему колбэки только кладут в очередь

`on_sent` и `on_received` вызывает **задача Wi-Fi**, а не наша. Если в них долго
работать (логи, разбор, ожидание очередей), радио начнёт терять пакеты. Поэтому колбэк
только копирует пакет в очередь (без ожидания), а логи и рассылку делает `task_espnow_link`.

## Пакет

```cpp
typedef struct {
    uint8_t mac[6];       // от кого (для принятых)
    uint8_t len;          // сколько байт в data
    uint8_t data[250];
} espnow_packet_t;
```

Принятые данные **не** заканчиваются `'\0'`: читать по `len`. Отправляется команда
тоже без `'\0'` — по радио уходит ровно `:Me#` (4 байта).

## Задача

| Параметр | Значение |
|---|---|
| Очередь | 10 событий (~260 байт каждое) |
| Стек | 3584 байта |
| Ожидание очереди | без таймаута; во время поиска — 500 мс (повтор `?PAIR`) |
| Приоритет | 8: выше `mount_link` (7), пакет уходит сразу, как его положили |

## Порядок запуска

`espnow_link_init()` — **до** `mount_link_init()`: mount_link отправляет через него.
Если запуск не удался, `app_main` пишет ошибку и продолжает: экран и меню работают, но
команды до монтировки не дойдут.

## Ограничения и TODO

- Принятые LX200-пакеты пока только пишутся в лог: подписчиков RX нет. Когда монтировка
  начнёт отвечать, `mount_link` подпишется и будет разбирать ответы (info/menu.md, раздел 9).
- Фильтр «пакет от своей монтировки» сделан в задаче, а не в колбэке: MAC меняет задача,
  а колбэк работает в задаче Wi-Fi.
- Шифрования нет (`encrypt = false`).
- У части плат C3 SuperMini слабая антенна: если связь рвётся — попробовать
  `esp_wifi_set_max_tx_power()` (см. hand-controller.md монтировки).
- Монтировке нужна такая же часть: ESP-NOW на том же канале, ответ `!PAIR`, приём LX200
  из пакетов ([info/pairing.md](../../info/pairing.md), раздел 4).
