# oled_device — драйвер экрана SSD1306

## Какую задачу решает

Экран GME12864-41 (контроллер SSD1306, 128 × 64, I²C адрес `0x3C`) сам текст
рисовать не умеет: ему надо прислать каждый пиксель. Модуль хранит копию экрана
в RAM (буфер кадра), рисует в неё текст и линии, а потом одной посылкой
отправляет весь кадр на экран.

```
oled_clear() ─► oled_draw_text() ─► oled_draw_hline() ─► oled_flush()
         рисование в RAM (быстро, без I²C)              1 КБ по I²C (~25 мс)
```

## Файлы

| Файл | Что внутри |
|---|---|
| `oled_device.h` | размеры экрана и текстовой сетки, API |
| `oled_device.cpp` | настройка SSD1306, буфер кадра, рисование, отправка |
| `oled_font.h` | шрифт 5 × 7 для символов ASCII `0x20`…`0x7E` |

## Как устроена память экрана

Экран разбит на 8 **страниц** по 8 пикселей в высоту. Один байт = вертикальный
столбик из 8 пикселей (бит 0 — верхний):

```
           столбец 0  столбец 1 ... столбец 127
страница 0   байт       байт          байт      ← строка текста 0 (пиксели y 0..7)
страница 1   байт       байт          байт      ← строка текста 1 (пиксели y 8..15)
...
страница 7                                      ← строка текста 7
итого 8 × 128 = 1024 байта
```

Поэтому одна строка текста = одна страница, и вывод символа — просто
копирование 5 байт шрифта.

## Текстовая сетка

| | Значение |
|---|---|
| Ячейка символа | 6 × 8 (символ 5 × 7 + пустой столбец) |
| Символов в строке | 21 (`OLED_TEXT_COLS`) |
| Строк | 8 (`OLED_TEXT_ROWS`) |

Символ вне шрифта рисуется как `?`, текст длиннее строки обрезается.

## Как общаться с SSD1306 по I²C

Первый байт посылки говорит, что идёт дальше:

| Первый байт | Дальше |
|---|---|
| `0x00` | команды (настройка, окно записи) |
| `0x40` | данные (пиксели) |

Буфер `frame_tx` = `0x40` + 1024 байта кадра. Байт `0x40` лежит прямо перед
кадром, поэтому кадр уходит одной передачей, без копирования.

## Функции

| Функция | Что делает |
|---|---|
| `init_oled()` | добавить экран на шину (400 кГц) |
| `i2c_oled_check()` | тест: включить экран и зажечь все пиксели (`0xA5`) |
| `oled_display_init()` | полная настройка SSD1306 (`0xA4` отменяет тест), очистка экрана |
| `oled_clear()` | очистить буфер кадра |
| `oled_draw_text(row, col, text)` | текст в буфер, `row` 0..7, `col` 0..20 |
| `oled_draw_hline(y)` | горизонтальная линия на всю ширину |
| `oled_flush()` | окно «весь экран» + кадр. Берёт `i2c_mutex` |
| `oled_set_contrast(value)` | яркость: команда `0x81` + `value` (0x00–0xFF). Буфер кадра не трогает. Берёт `i2c_mutex` |

## Правило

Буфер кадра один на всю программу, поэтому в каждый момент рисует одна задача —
та, у которой экран (`task_main_screen` или `task_menu`). Экран они передают
друг другу сообщением `SCREEN_MSG_SHOW` ([main_screen.md](../main_screen/main_screen.md)).

## Известные моменты

- `i2c_oled_check()` не берёт `i2c_mutex`. Вызывается в `app_main` до запуска задач,
  поэтому сейчас это безопасно.
- `oled_display_init()` ставит контраст `0x7F`, а сразу после него `app_main` вызывает
  `oled_set_contrast(settings_get_contrast())`: экран стартует с яркостью из настроек.
- Контраст у SSD1306 регулирует яркость слабо: экран не гаснет почти до нуля.
  Для более тёмного ночного режима можно уменьшать ещё предзаряд (`0xD9`) и VCOMH (`0xDB`).
- У экранов 1.3" часто стоит SH1106: у него другая адресация, и `oled_flush()` пришлось бы переписать.
