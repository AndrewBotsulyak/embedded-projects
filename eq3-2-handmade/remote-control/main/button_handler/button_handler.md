# button_handler — чтение кнопок

## Какую задачу решает

7 кнопок подключены к расширителю MCP23017, а не к ESP32. Когда кнопка
меняется, MCP23017 опускает линию INTA (GPIO3). Модуль ловит это прерывание,
читает кнопки по I²C, определяет, какие нажали и какие отпустили, и отправляет
события в очереди задач, которые подписались (`button_subscribe`).

```
кнопка ──► MCP23017 ──INTA (0)──► GPIO3 ──► прерывание ──► task_button_handler
                                                              │ читает GPIOA по I²C
                                                              ▼
                                                    screen_msg_t {SCREEN_MSG_BUTTON, кнопка, нажал/отпустил}
                                                    → в очередь каждого подписчика (menu, main_screen)
```

## Файлы

| Файл | Что внутри |
|---|---|
| `button_handler.h` | пин INTA (`BTN_CLICK_PIN` = GPIO3), маски кнопок, `button_id_t`, `button_action_t`, API |
| `button_handler.cpp` | обработчик прерывания, задача чтения, таблица «бит → кнопка» |

## Маски кнопок (порт A MCP23017)

| Бит | Маска | Кнопка |
|---|---|---|
| GPA0 | `STOP_BUTTON` | STOP |
| GPA1 | `MENU_BUTTON` | MENU |
| GPA2 | `ENTER_BUTTON` | ENTER |
| GPA3 | `RIGHT_BUTTON` | ► |
| GPA4 | `LEFT_BUTTON` | ◄ |
| GPA5 | `DOWN_BUTTON` | ▼ |
| GPA6 | `UP_BUTTON` | ▲ |

Бит = 1 — кнопка нажата (MCP23017 настроен на инверсию чтения).

## Как работает задача

| Шаг | Что | Зачем |
|---|---|---|
| 1 | ждать уведомление от прерывания | задача спит, пока кнопки не трогают |
| 2 | ждать, пока 20 мс не будет новых прерываний | антидребезг: контакт кнопки «дребезжит» несколько мс |
| 3 | если INTA уже 1 — пропустить | короткая помеха |
| 4 | взять `i2c_mutex`, прочитать GPIOA | на шине I²C ещё OLED |
| 5 | `pressed = buttons & ~prev`, `released = prev & ~buttons` | только **изменения**, а не текущее состояние |
| 6 | отправить отпускания, потом нажатия | «отпустил ◄, нажал ►» → сначала `:Qw#`, потом `:Me#` |

Пример шага 5:

```
prev     = 0001_0000   (◄ нажата)
buttons  = 0000_1000   (► нажата, ◄ отпущена)
pressed  = 0000_1000   → ►  PRESS
released = 0001_0000   → ◄  RELEASE
```

## Почему прерывание только «будит» задачу

Внутри прерывания нельзя работать с I²C: передача долгая и использует мьютекс.
Поэтому прерывание только вызывает `vTaskNotifyGiveFromISR`, а читает задача.

## Приоритет

Задача кнопок — 10, экраны — 5: кнопки читаются сразу, даже пока экран рисуется.

Ещё это гарантирует порядок: задача кнопок успевает положить событие **во все**
очереди подписчиков, прежде чем любой экран начнёт его обрабатывать.

## Порядок запуска

`init_btn_handler()` вызывать **последним**: к этому моменту `menu_init()` и
`main_screen_init()` уже подписали свои очереди.

## Подписка

| Функция | Что делает |
|---|---|
| `button_subscribe(queue)` | добавить очередь `screen_msg_t` в список (до 4). Вызывать до `init_btn_handler()` |

Кнопки не знают, кто подписан: они просто кладут сообщение в каждую очередь из списка.
Если очередь полна, событие для неё теряется (в лог — предупреждение).
