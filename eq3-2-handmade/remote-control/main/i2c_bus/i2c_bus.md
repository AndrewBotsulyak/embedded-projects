# i2c_bus — общая шина I²C

## Какую задачу решает

На двух проводах I²C висят два устройства: MCP23017 (кнопки) и OLED. Шину нужно
создать **один раз**, а потом подключать к ней устройства. Кроме того, к шине
обращаются разные задачи (кнопки, main_screen, menu), и их передачи нельзя перемешивать.
Модуль создаёт шину и мьютекс для неё.

```
               ┌── MCP23017 (0x20, 100 кГц) ◄── task_button_handler
ESP32-C3 ─I²C──┤
               └── OLED     (0x3C, 400 кГц) ◄── task_main_screen / task_menu (у кого экран)
                        ▲
                    i2c_mutex: в каждый момент шиной пользуется одна задача
```

## Файлы

| Файл | Что внутри |
|---|---|
| `i2c_bus.h` | пины SCL/SDA, `extern bus_handle`, `extern i2c_mutex`, `i2c_init()` |
| `i2c_bus.cpp` | создание шины и мьютекса |

## Настройка шины

| Параметр | Значение | Почему |
|---|---|---|
| порт | `I2C_NUM_0` | у ESP32-C3 один контроллер I²C |
| SCL / SDA | GPIO6 / GPIO7 (`I2C_SCL_PIN`, `I2C_SDA_PIN`) | |
| фильтр помех | 7 тактов | короткие выбросы на линии игнорируются |
| внутренние подтяжки | выключены | стоят внешние резисторы на модулях |
| `allow_pd` | 0 | у ESP32-C3 нельзя выключать питание шины во сне |

Скорость задаётся у каждого устройства отдельно (при подключении к шине).

## Мьютекс

Каждая передача по шине обёрнута так:

```cpp
xSemaphoreTake(i2c_mutex, portMAX_DELAY);   // занять шину (ждать, если занята)
... i2c_master_transmit / transmit_receive ...
xSemaphoreGive(i2c_mutex);                  // освободить
```

Без этого чтение кнопок могло бы начаться посреди отправки кадра OLED.

## Порядок запуска

`i2c_init()` вызывается первой в `app_main`: `init_mcp()` и `init_oled()` используют `bus_handle`.

## Известные моменты
