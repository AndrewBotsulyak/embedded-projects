# main_screen — задача главного экрана

## Какую задачу решает

Главный экран — то, что видно, когда меню закрыто. Здесь стрелки двигают монтировку,
ENTER меняет скорость стрелок, MENU отдаёт экран меню. Всё это делает **одна задача**
`task_main_screen`. Она сама решает, что значит кнопка, и сама себя рисует.
Другие задачи только присылают ей сообщения в очередь.

```
task_button_handler ── SCREEN_MSG_BUTTON ───────►┐
task_mount_link     ── SCREEN_MSG_MOUNT_CHANGED ─┼──► очередь ──► task_main_screen
task_menu           ── SCREEN_MSG_SHOW ─────────►┘                 │
                                                                   ├── main_view_draw()      (OLED)
                                                                   ├── arrows_*  ──► mount_link (очередь)
                                                                   └── MENU: menu_show(своя очередь)
```

## Файлы

| Файл | Кто использует | Что внутри |
|---|---|---|
| `main_screen.h` | `app_main` | только `main_screen_init()` |
| `main_screen.cpp` | — | очередь, задача, что значит каждая кнопка |
| `main_view.h/.cpp` | только эта задача | отрисовка главного экрана |
| `arrows.h/.cpp` | только эта задача | зажатые стрелки, повтор `:M?#` ([arrows.md](arrows.md)) |

## Экран: у кого он сейчас

Экран один, а задач-экранов две (main_screen и menu). Рисует только та, у которой
`active = true`. Экран передаётся сообщением `SCREEN_MSG_SHOW`:

```
task_main_screen (active)          task_menu
   │ нажали MENU
   │ отпустить стрелки (:Q?#)
   │ active = false
   │ ── menu_show(main_queue) ──►  active = true, рисует меню
   │                               ...
   │                               меню закрыли (MENU или ◄ на верхнем уровне)
   │                               active = false
   │ ◄── SCREEN_MSG_SHOW ─────────
   │ active = true, рисует главный экран
```

Кнопки приходят **обеим** задачам (обе подписаны), но реагирует только активная.

## Что делает кнопка

| Кнопка | Когда | Действие |
|---|---|---|
| **STOP** | всегда, даже если экран у меню | забыть стрелки, `:Q#` |
| стрелка нажата | экран у main_screen | `:R?#` + `:M?#`, повтор каждые 200 мс |
| стрелка отпущена | всегда | `:Q?#`, если стрелка была зажата |
| ENTER | экран у main_screen | следующая скорость по кругу, `:R?#` |
| MENU | экран у main_screen | отпустить стрелки, отдать экран меню |

**Почему STOP обрабатывает эта задача, а не mount_link.** Повтор `:M?#` идёт отсюда.
Если бы `:Q#` отправлял кто-то другой, повтор мог бы попасть в очередь монтировки
**после** `:Q#` и снова запустить ось. Здесь порядок гарантирован: сначала стрелки
забыты, потом `:Q#`.

## Сообщения

| Сообщение | Действие |
|---|---|
| `SCREEN_MSG_BUTTON` | таблица выше |
| `SCREEN_MSG_SHOW` | экран вернули: `active = true`, перерисовать |
| `SCREEN_MSG_MOUNT_CHANGED` | перерисовать, если экран у main_screen (Tracking изменился) |

## Задача

| Параметр | Значение |
|---|---|
| Очередь | 16 × `screen_msg_t` |
| Стек | 3072 байта |
| Приоритет | 5 (как menu; ниже кнопок 10 и mount_link 7) |
| Ожидание очереди | без таймаута; пока зажата стрелка — 200 мс (для повтора) |

## Порядок запуска

`main_screen_init()` — после `mount_link_init()` и `menu_init()` (на них подписка и
`menu_show`), до `init_btn_handler()`. Первый кадр задача рисует сама.
