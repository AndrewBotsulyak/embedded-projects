# Сопряжение пульта и монтировки (ESP-NOW)

Как пульт узнаёт MAC монтировки, где его хранит и что для этого должна уметь
прошивка монтировки. Сторона пульта сделана в
[espnow_link](../main/espnow_link/espnow_link.md), сторона монтировки — пока нет.

---

## 1. Зачем

ESP-NOW отправляет пакет на **MAC-адрес** платы. Пока пульт не знает MAC монтировки,
он шлёт команды всем (broadcast `FF:FF:FF:FF:FF:FF`):

| | Не сопряжены (broadcast) | Сопряжены (MAC монтировки) |
|---|---|---|
| Кто получит `:Me#` | любая ESP-NOW плата на канале | только своя монтировка |
| Подтверждение доставки | нет | есть: при неудаче лог `TX not delivered` |
| От кого принимаем | от любой платы | только от своей монтировки |

Вписывать MAC в код руками неудобно: при замене платы надо перепрошивать пульт.
Поэтому MAC узнаётся **командой из меню** и хранится во flash (NVS).

---

## 2. Протокол

Два служебных сообщения. Они начинаются **не** с `:`, поэтому не путаются с LX200
(команды LX200 всегда начинаются с `:` или байта `0x06`).

| Сообщение | Кто → кому | Что значит |
|---|---|---|
| `?PAIR` | пульт → **все** (broadcast) | «кто тут монтировка?» |
| `!PAIR` | монтировка → **пульт** (лично, на MAC отправителя `?PAIR`) | «я» |

5 байт ASCII, без `'\0'` и без `#`. MAC внутри сообщения не передаётся:
ESP-NOW сам сообщает адрес отправителя (`src_addr` в колбэке приёма).

```
ПУЛЬТ  MENU → Link → Pair                         МОНТИРОВКА (в режиме сопряжения)
 │
 │ ?PAIR  → FF:FF:FF:FF:FF:FF
 │ ──────────────────────────────────────────►   src_addr = MAC пульта
 │ (повтор каждые 500 мс)                        сохранить MAC пульта в NVS
 │                                               добавить пульт в peer
 │ ◄──────────────────────────────────────────   !PAIR → MAC пульта
 │ src_addr = MAC монтировки
 │ сохранить в NVS, peer = MAC монтировки
 │ экран: Link  PAIRED, Mount  AA:BB:CC
```

Если за **10 с** ответа нет — поиск прекращается. Если до этого монтировка уже была
сопряжена, остаётся старый MAC (поиск не стирает его).

## 3. Пульт

### 3.1. Состояния

```
          старт, NVS пуст                       старт, MAC в NVS
                 │                                     │
                 ▼        Pair                         ▼
          ┌────────────┐ ──────► ┌──────────┐  !PAIR ┌────────┐
          │ NOT_PAIRED │         │ PAIRING  │ ─────► │ PAIRED │
          └────────────┘ ◄────── └──────────┘        └────────┘
                 ▲    10 с, не было MAC  │  ▲  Pair       │
                 │                       │  └────────────┘
                 │        10 с, MAC был  └──────► PAIRED (старый MAC)
                 │
                 └──────────────── Unpair ◄───────── из любого
```

| Состояние | На экране (Link) | Куда уходят команды |
|---|---|---|
| `NOT_PAIRED` | `NONE` | broadcast |
| `PAIRING` | `SEARCH..` | как было до поиска |
| `PAIRED` | `PAIRED` | MAC монтировки |

### 3.2. Меню

```
MENU                      LINK
> Speed     GUIDE         > Pair      PAIRED     ← ACTION: начать поиск; справа — состояние
  Tracking  OFF             Unpair               ← ACTION: забыть монтировку
  Display   LOW             Mount     AA:BB:CC   ← INFO: последние 3 байта MAC или "-"
  Link      PAIRED   ──►
```

Меню не ждёт результата: оно просит `task_espnow_link` начать поиск и перерисовывается,
когда приходит `SCREEN_MSG_LINK_CHANGED`.

### 3.3. Приём пакетов

| Пришло | Что делает пульт |
|---|---|
| `!PAIR` во время поиска | MAC отправителя = MAC монтировки, сохранить |
| `!PAIR` не во время поиска | игнорировать |
| любое сообщение на `?` или `!` | игнорировать (служебное, например `?PAIR` другого пульта) |
| остальное, сопряжены, от чужого MAC | отбросить |
| остальное | лог + подписчикам `espnow_link_subscribe_rx` |

### 3.4. Хранение

| | |
|---|---|
| Где | NVS, namespace `espnow`, ключ `peer_mac`, blob 6 байт |
| Когда пишется | монтировка найдена |
| Когда стирается | Unpair |
| Когда читается | `espnow_link_init()` при старте |

### 3.5. Код

| Что | Где |
|---|---|
| протокол, NVS, peer, поиск | [espnow_link.cpp](../main/espnow_link/espnow_link.cpp) — `pair_start`, `pair_tick`, `handle_rx`, `set_peer`, `unpair` |
| константы `ESPNOW_PAIR_*` | [espnow_link.h](../main/espnow_link/espnow_link.h) |
| пункты меню | [menu_items.cpp](../main/menu/menu_items.cpp) — `LINK_ITEMS` |

## 4. Что нужно на монтировке

| Что | Как |
|---|---|
| ESP-NOW на том же канале | `ESPNOW_LINK_CHANNEL` = 1, broadcast peer для приёма не нужен |
| Отделить служебное от LX200 | пакет на `?` / `!` — сопряжение; остальное — в парсер LX200 (свой канал, как `lx200_usb`) |
| Ответ на `?PAIR` | только **в режиме сопряжения**: добавить MAC отправителя в peer, сохранить в NVS, ответить `!PAIR` лично ему |
| Режим сопряжения | первые ~30 с после включения **или** по кнопке на плате. Иначе на `?PAIR` ответит любая такая монтировка рядом |
| Принимать LX200 | только от сохранённого MAC пульта (если он есть) |
| Отвечать на LX200 (`:Te#` → `1`) | лично пульту, на его MAC |

---

## 5. Ограничения

- Шифрования нет: кто знает протокол, может послать команду. Для дома и выезда
  этого достаточно. Если понадобится — ESP-NOW умеет шифровать (`encrypt = true` + ключ `lmk`).
- Если `!PAIR` ответят две монтировки, пульт возьмёт **первую**. Защита от этого —
  режим сопряжения на монтировке (раздел 4).
- Сообщения `?PAIR`/`!PAIR` описаны только в пульте. Когда появится сторона монтировки,
  их стоит перенести в общий компонент `components/`, чтобы обе прошивки брали одни строки.
