# План разработки

Порядок, в котором имеет смысл двигаться, и критерии, по которым понятно, что
этап закрыт.

Соседние документы: [controller-options.md](controller-options.md) — из чего
собирать, [astro-info.md](astro-info.md) — астрономия,
[stepper.md](stepper.md) — мотор и драйвер,
[technical-configurations.md](technical-configurations.md) — настройки железа,
[../Readme.md](../Readme.md) — сборка проекта.

---

## Главный принцип

> **После каждого этапа на руках работающее устройство.**

Не «полгода ничего не работает, потом всё сразу». Каждый этап добавляет
возможность, которой можно пользоваться, и его можно бросить на любом шаге —
то, что сделано, останется полезным.

Второй принцип: **сначала измерить, потом считать.** Половина кода в проекте
опирается на числа, которые пока взяты на веру. Пока они не проверены, любая
сложная математика поверх них бессмысленна.

```
   Этап 0: измерения

        ▼

               ▼

               │
               ▼
        Этап 8: доводка
```

## Этап 0 — измерить железо

**Зачем.** Сейчас три числа в коде — предположения. Любая ошибка в них ломает всё
поверх, причём молча: код будет считать безупречно, а труба поедет не туда.

| Задача | Где смотреть |
|---|---|
| ☐ Замерить `R_sense` тестером на обесточенной плате | [tmc-uart.h](../main/tmc-module-uart/tmc-uart.h) |
| ☐ Списать паспортный ток моторов с шильдика | «Rated current, A/phase» |
| ☐ Пересчитать зубья червячных колёс обеих осей | ожидаем RA 130, DEC 65 |
| ☐ Проверить, есть ли понижающая передача мотор → червяк | |
| ☐ Замерить напряжение силового питания | |
| ☐ Найти механические пределы осей — где труба упирается | |

**Критерий готовности:** в
[technical-configurations.md](technical-configurations.md) и
[../Readme.md](../Readme.md) не осталось пометок ⚠️.

## Этап 1 — довести ведение

**Зачем.** Это уже полезный прибор: визуальные наблюдения на любом увеличении и
короткие выдержки без смаза.

| Задача | Примечание |
|---|---|
| ☐ Подставить измеренные значения в константы | |
| ☑ Разделить передаточные числа на RA и DEC | сделано: `AXIS1_WORM_TEETH` 130, `AXIS2_WORM_TEETH` 65 |
| ☑ Раздельные токи по осям, покой выше 50% | сделано: RA 70%, DEC 90% |
| ☐ Прочитать `DRV_STATUS` и проверить `CS_ACTUAL` при ведении | не проваливается ли ток до IHOLD |
| ☐ Тепловой тест под нагрузкой | корпус мотора тёплый, но руку держать можно |
| ☐ Проверить удержание на `IHOLD` | монтировка с противовесом не проворачивается |
| ☐ Прогнать ведение всю ночь | не срывается, не греется, не пропускает шагов |

**Критерий готовности:** звезда стоит в окуляре на большом увеличении полчаса.

**Что будет работать:** трекер. Уже можно наблюдать и снимать выдержки до
десятков секунд.

## Этап 2 — точное время

**Зачем.** Без времени координатной математики не существует в принципе: чтобы
перевести координаты объекта в углы поворота осей, нужно знать местное звёздное
время, а оно считается из UTC и долготы.

| Задача | Примечание |
|---|---|
| ☐ Выбрать источник: RTC DS3231 или GPS-модуль | GPS даёт ещё и координаты места |
| ☐ Хранение широты и долготы наблюдателя | в NVS |
| ☐ Расчёт местного звёздного времени | тут уже пригодится Astronomy Engine |
| ☐ Синхронизация времени по NTP, когда есть WiFi | |

**Критерий готовности:** прошивка печатает местное звёздное время, и оно
совпадает с тем, что показывает планетарий на телефоне.

## Этап 4 — протокол LX200 по WiFi

**Зачем.** Вот здесь привод становится «умным». До этого этапа он исполняет
заложенную программу, после — им можно управлять готовым софтом.

| Задача | Примечание |
|---|---|
| ☐ Поднять WiFi и TCP-сервер | |
| ☐ Разбор команд LX200 | ASCII вида `:GR#`, `:Sr HH:MM:SS#` |
| ☐ Отдавать текущие координаты | `:GR#`, `:GD#` |
| ☐ Принимать целевые координаты | `:Sr`, `:Sd` |
| ☐ Синхронизация позиции по объекту | `:CM#` |
| ☐ Управление скоростью с пульта | `:Mn#`, `:Ms#`, `:Me#`, `:Mw#`, `:Q#` |

**Критерий готовности:** SkySafari или Stellarium на телефоне видит привод,
показывает, куда он смотрит, и умеет им двигать.

**Что будет работать:** ручное управление с телефона, синхронизация по звезде.
GOTO ещё нет, но каркас для него готов.

## Что можно делать параллельно

Этапы 3 и 4 друг от друга не зависят: вторую ось и протокол можно вести
одновременно. Всё остальное выстроено в цепочку — каждый следующий этап
опирается на предыдущий.

Этап 0 стоит первым не из педантизма. Измерения делаются паяльником и отвёрткой,
а не за клавиатурой, и если их отложить, то вся математика этапов 5 и 6 будет
отлаживаться поверх неизвестных — а это худший способ искать ошибку.

## Отдельный ход: измерить механику чужими руками

На этапе 0 есть короткий путь. Дешёвый классический ESP32 плюс готовая прошивка
OnStepX дают передаточное число, периодическую ошибку и люфт **без отладки
собственного кода**. Механика и прошивка перестают быть одной неизвестной и
разделяются на две.

Подробности — в
[controller-options.md](controller-options.md#измерить-механику-чужими-руками).
