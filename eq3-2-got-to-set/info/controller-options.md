# Из чего собирать умный привод

Разбор вариантов: готовые прошивки, библиотеки, протоколы. По состоянию на
**11 сентября 2026** — информация о версиях и поддержке плат устаревает, перед
решением перепроверь по ссылкам в конце.

Соседние документы: [roadmap.md](roadmap.md) — план разработки,
[astro-info.md](astro-info.md) — астрономия, [stepper.md](stepper.md) — мотор и
драйвер, [technical-configurations.md](technical-configurations.md) — настройки
железа, [../Readme.md](../Readme.md) — сборка проекта.

---

## Краткий вывод

**Не надо выбирать монолитную прошивку — надо собирать по слоям.**

OnStep, OpenAstroTracker и AstroEQ делают всё сразу и потому несовместимы с
существующим кодом: это не зависимости, а замена проекта целиком. При этом
задача честно делится на четыре независимых слоя, и для каждого свой выбор.

Рекомендуемый стек для нашего железа: **свой код движения + Astronomy Engine на
математику + LX200 по WiFi на протокол**, а OnStepX — как справочник для сверки.

Побочная находка, закрывающая давний вопрос: **передаточные числа EQ3-2 — RA
130:1, DEC 65:1.**

---

## 0. Передаточные числа EQ3-2

Найдены в конфигурации AstroEQ для этой монтировки и подтверждены обсуждениями
в сообществе EQMOD.

| Ось | Зубьев червячного колеса |
|---|---|
| **RA** | **130** |
| **DEC** | **65** |

Следствия:

- Расчёт скорости ведения в проекте **верен** — 130 угадано правильно.
- **У DEC вдвое меньше**, поэтому передаточные числа в
  [../main/stepper/stepper.h](../main/stepper/stepper.h) заданы раздельно:
  `AXIS1_WORM_TEETH` = 130, `AXIS2_WORM_TEETH` = 65.
- **Разрешение DEC вдвое хуже**: 6.23″ на микрошаг против 3.11″ у RA.
  Для коррекций гидирования это грубо — понижающий ремень на DEC нужнее, чем
  на RA.

Зубья всё равно стоит пересчитать глазами, но теперь есть с чем сверять.

Попутно там же: штатный моторный комплект Sky-Watcher для EQ3-2 использует мотор
7.5° с редуктором 120:1 на RA и 80:1 на DEC. К нашей схеме с NEMA 17 напрямую на
червяк это не относится, но объясняет, почему числа в чужих конфигах могут
отличаться.

## 2. Слой 4: протокол — самое важное решение

**«Умный» привод — это в первую очередь тот, с которым умеет говорить готовый
софт.** Реализуешь известный протокол — бесплатно получаешь Stellarium, SkySafari
на телефоне, N.I.N.A., PHD2 для гидирования. Не реализуешь — пишешь своё
приложение с нуля.

| Протокол | Что даёт | Сложность | Вердикт |
|---|---|---|---|
| **LX200** (Meade) | Stellarium, SkySafari, CdC, ASCOM | **низкая** — текстовые команды | ✅ лучший старт |
| **ASCOM Alpaca** | N.I.N.A., всё ASCOM, без USB-драйверов | средняя — HTTP + JSON | ✅ современный |
| SkyWatcher / EQMOD | EQMOD, EQASCOM | высокая — бинарный | ⚠️ в основном Windows |
| Stellarium TCP | только Stellarium | очень низкая | слишком узко |
| INDI | экосистема Linux | — | ❌ **не работает на МК**, нужен Linux |

**LX200 — самый быстрый путь к «умному».** Обычные ASCII-команды: `:GR#` —
«дай прямое восхождение», `:Sr HH:MM:SS#` — «установи цель». Рабочее подмножество
занимает около трёхсот строк. Именно его используют и OnStep, и OpenAstroTracker.

**Alpaca — вариант посовременнее**, и для нашей сборки есть прямое попадание:
[esp32-idf-ascom-alpaca](https://github.com/darkdragonsastro/esp32-idf-ascom-alpaca)
написан на **нативном ESP-IDF**, то есть ровно наша система сборки. Оговорка: тип
устройства Telescope там как раз не реализован (есть все остальные) — но
HTTP-сервер, discovery и сериализация JSON готовы, а это самая скучная часть.

## 3. Слой 2: астрономическая математика

| Библиотека | Язык | Лицензия | Замечания |
|---|---|---|---|
| **[Astronomy Engine](https://github.com/cosinekitty/astronomy/tree/master/source/c)** | C, один файл | MIT | точность ~1′, уже используют на ESP32 |
| libnova | C | LGPL | полнее, но тяжелее для микроконтроллера |
| ERFA / SOFA | C | своя | максимальная точность, избыточно |

Точность в одну угловую минуту звучит скромно, но для наводки этого достаточно:
собственные ошибки EQ3-2 крупнее. А на ведение точность каталога не влияет
вообще — там постоянная скорость.

## 4. Слой 3: модель наведения

Здесь готового почти нет, и это самая тяжёлая часть работы. Нужно уметь:

- синхронизироваться по одной звезде — простое смещение;
- по двум-трём звёздам вычислить ошибку полярной выставки,
  неперпендикулярность осей и конус трубы;
- учитывать атмосферную рефракцию — у горизонта объект видно выше на 30′;
- решать, на какой стороне от меридиана работать, и когда переворачиваться.

Референс — исходники OnStepX. Осторожно с GPL, см. раздел про лицензию.

## 5. Монолитные прошивки: сравнение

| Проект | Платформа | Протокол | Вердикт |
|---|---|---|---|
| **OnStepX** | ESP32, Teensy, STM32 | LX200 | самый мощный, но **нет ESP32-S3** и конфликт версии arduino-esp32 |
| **OpenAstroTracker** | Arduino, ESP32 | LX200 | проще OnStep, заточен под самодельные трекеры; версия 2.x на Zephyr ещё не готова |
| **AstroEQ** | Atmega162 (AVR) | SkyWatcher / EQMOD | **есть готовый конфиг EQ3-2**, но железо древнее |
| **TeenAstro** | Teensy | LX200 | форк OnStep с упором на пульт; чужая платформа |

Ни один не встанет на ESP32-S3 без переделки. Но **AstroEQ ценен как источник
данных** — именно оттуда взялись передаточные числа выше.

## 6. OnStepX подробно

OnStep — открытый контроллер телескопа, развивается с середины 2010-х.
OnStepX — переписанная современная ветка, её и надо рассматривать.

Формулировка из README проекта:

> complete firmware for computerized telescope controllers, **not a library for
> integration into other projects**

Это ключевой факт. Варианта «взять оттуда кусок математики как зависимость» не
существует — либо ты пишешь свою прошивку, либо заливаешь OnStepX и настраиваешь
его `Config.h`.

### Что OnStepX умеет из коробки

| Возможность | Подробности |
|---|---|
| Типы монтировок | GEM, GEM_TA, GEM_TAC, FORK, FORK_TA, FORK_TAC, ALTAZM, ALTAZM_UNL |
| Ведение | с компенсацией рефракции и по модели |
| GOTO | наводка с профилями разгона |
| Гидирование | ST-4 и команды по порту, `GUIDE_TIME_LIMIT` |
| PEC | запись и воспроизведение, `PEC_STEPS_PER_WORM_ROTATION` |
| Люфт | `TRACK_BACKLASH_RATE` |
| Драйверы | TMC2209/TMC2226 с настройкой по UART, плюс A4988, DRV8825 и другие |
| Дополнительные оси | до 6 фокусеров, ротатор поля |
| Связь | USB, Bluetooth, WiFi, Ethernet |
| Протокол | LX200 — работает со Stellarium, SkySafari, CdC, ASCOM/INDI |
| Периферия | RTC DS3231, GPS, датчики home, энкодеры, метеодатчик |

### Лицензия

**GPL-3.0.**

Практически это значит:

- **Личный проект, который никуда не публикуется** — GPL не требует ничего.
  Лицензия срабатывает только при распространении.
- **Выложил на GitHub, скопировав их код** — твой проект обязан стать GPL-3.0.
- **Прочитал, понял алгоритм, написал своё** — ограничений нет.

### Препятствия для нашего железа

Проверять до того, как что-то ломать.

#### ESP32-S3 не поддержан

Полный список пинмапов из `src/Constants.h` версии на дату разбора:

```
FYSETC_E4            MiniPCB, MiniPCB13, MiniPCB2
FYSETC_S6, _S6_1, _S6_2   MaxPCB, MaxPCB2, MaxPCB3, MaxPCB4
BTT_SKR_PRO          MaxSTM3, MaxSTM3I
BTT_OCTOPUS_PRO      MaxESP3, MaxESP4
CNC3                 MicroScope
STM32Blue            JTWSTM
MANTICORE            SAL_XB1
```

Все ESP32-варианты — **классический ESP32**:

| Пинмап | Плата |
|---|---|
| `MaxESP3` | WeMos D1 Mini WiFi |
| `MaxESP4` | ESP32S с поддержкой TMC2209 |
| `CNC3` | WeMos D1 R32 (ESP32) |
| `FYSETC_E4` | ESP32 |

Слова `S3` в файле нет вообще. У нас
[ESP32-S3-DevKitC-1](../Readme.md).

#### Конфликт версии Arduino-слоя

Вики OnStep рекомендует **arduino-esp32 2.0.17** и сообщает, что 3.x не
поддерживается. В [../main/idf_component.yml](../main/idf_component.yml) у нас
стоит **3.3.11**.

#### Разные системы сборки

| | OnStepX | Наш проект |
|---|---|---|
| Формат | Arduino-скетч `OnStepX.ino` | ESP-IDF компонент |
| Точка входа | `setup()` / `loop()` | свой `app_main()` |
| Сборка | Arduino IDE / PlatformIO | `idf.py`, `CMakeLists.txt` |
| Arduino | основа | подключён как компонент, `initArduino()` |

Это не «добавить файлы в проект» — это другой проект.

**Итог:** переход на OnStepX означает **сменить плату** на классический ESP32 и
начать с их сборкой с нуля. Это не упрощение работы, а замена одной работы
другой.

## 7. Сколько математики у нас уже сделано

Ответ зависит от цели, и он неприятный: репозиторий называется `eq3-2-goto`.

| Задача | Готово | Что осталось |
|---|---|---|
| **Ведение** | ~90% | подтвердить число зубьев червяка |
| **GOTO** | ~5% | почти всё, см. ниже |

Для чистого ведения работа почти закончена: скорость постоянна, считается одной
формулой, формула написана и проверена. Для наводки эта формула — один параметр
из двух десятков.

### Чего нет для GOTO

- **Местное звёздное время** из UTC и долготы — нужны RTC или GPS;
- **Часовой угол** = звёздное время − прямое восхождение объекта;
- **Перевод координат** RA/Dec → углы поворота осей монтировки;
- **Модель наведения** — поправки на ошибку полярной выставки,
  неперпендикулярность осей, конус трубы, прогиб. Самая тяжёлая часть:
  калибровка по 1–3 звёздам и решение системы уравнений;
- **Атмосферная рефракция** — у горизонта объект видно выше, чем он есть,
  до 30 угловых минут;
- **Логика меридианного переворота** и механические пределы осей;
- **Согласованное движение двух осей** с профилями разгона;
- **Компенсация люфта** при смене направления;
- **Протокол LX200** — иначе управлять нечем, кроме своих средств;
- **PEC** — запись и воспроизведение кривой периодической ошибки.

Это месяцы работы, если писать самому и разбираться по ходу. Разбито на этапы
в [roadmap.md](roadmap.md).

## 8. Рекомендуемый стек

```
   Stellarium / SkySafari / N.I.N.A. / PHD2
                    │
              LX200 по WiFi TCP        ← пишем сами, ~300 строк
                    │
         ┌──────────┴──────────┐
         │   НАША ПРОШИВКА     │
         │                     │
         │  Astronomy Engine   │       ← берём готовое
         │  модель наведения   │       ← пишем сами, референс OnStepX
         │  stepper + TMC2209  │       ← уже готово
         └─────────────────────┘
```

Ключевое отличие от «залить OnStepX»: на каждом шаге остаётся **работающее
устройство**, а не «полгода ничего, потом всё сразу».

Порядок работ расписан в отдельном документе — [roadmap.md](roadmap.md).

### Сверка формул уже доступна

OnStepX считает `AXIS1_STEPS_PER_DEGREE` так:

```
шаги_мотора × микрошаги × общее_передаточное ÷ 360
```

Подставляем наши числа:

```
200 × 16 × 130 ÷ 360 = 1155.6 шага на градус
```

Это ровно наш `AXIS1_STEPS_PER_REV = 416 000`, выраженный на градус:
`416 000 ÷ 360 = 1155.6`. **Формулы совпадают** — значит считаем правильно.

### Измерить механику чужими руками

Отдельный практический ход: купить дешёвый классический ESP32 и залить на него
OnStepX — **не чтобы им пользоваться, а чтобы проверить механику.**

Сразу станут известны реальное передаточное число, величина периодической
ошибки, люфт и механические пределы осей — и всё это без отладки собственного
кода. Механика и прошивка перестают быть одной неизвестной. Стоит порядка десяти
долларов и экономит недели.
